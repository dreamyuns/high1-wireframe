REF-5 PMS 연동 고려사항 — 개발사 전달용 · For Developers
1. 개요 / Overview

이 문서는 High1 어드민과 강원랜드 OTA PMS 연동 시 개발사가 반드시 고려해야 할 구조·규칙·미결 항목을 정의합니다.
This document defines the integration architecture, business rules, and open items that developers must address when integrating High1 Admin with Kangwon Land's OTA PMS.

2. 연동 모드 구조 / Integration Mode

모든 상품(Product)은 생성 시 연동 모드를 선택합니다. 모드는 생성 후 변경 불가합니다.

4. 동기화 구조 / Sync Architecture

동기화를 상품 정보와 재고·요금 두 가지로 분리합니다. 민감도와 변경 빈도가 다르기 때문입니다. 재고·요금 동기화는 객실 타입 단위(S04-INV)로 일원화되어 있으며, 재고와 요금을 하나의 버튼으로 함께 갱신합니다.
Sync is split into Product Info and Inventory & Price due to different sensitivity and change frequency. Inventory & Price sync is unified at the room-type level (S04-INV) and updated together via a single button.

상품 등록 후 최초 1회 수동 동기화 필수. 이후 배치 자동 업데이트 기본. 배치 실패 시 수동 버튼으로 fallback 가능합니다.
The Inventory & Price sync button is unified at S04-INV (room-type level). S06 (product) has no price-sync button, and inventory & price in S06-A/B/C are read-only. Inventory comes from API 4, price from API 3. Initial sync is required once manually after product registration; afterwards batch auto-update runs. Manual button available as batch failure fallback.

6. 예약 취소 흐름 / Cancellation Flow

부분취소 = 위약금이 발생하는 전체 취소 (일부 박수 취소 아님). 실제 환불은 결제 시스템(API 11/12)이 처리하며 어드민 범위 외입니다.
Partial cancellation = full cancellation with a penalty fee (not partial night cancellation). Actual refund is handled by the payment system (API 11/12) and is out of admin scope.

1
API 10 호출 → 위약금 금액(DLFT_APLY_AMT)·구간명(DFLT_NM) 수신
Call API 10 → Receive penalty amount and segment name
2
어드민 화면: "위약금 N원이 발생합니다. 취소하시겠습니까?" 팝업 표시
Admin screen: Show popup "A penalty of N KRW will apply. Confirm cancellation?"
3
관리자 확인 → API 7 호출 → PMS에서 예약 취소 처리 (RSV_STAT_CD: HB00600X)
Manager confirms → Call API 7 → PMS processes cancellation (RSV_STAT_CD: HB00600X)
4
환불 처리 → 결제 시스템 담당 (어드민 범위 외)
Refund → Handled by payment system (out of admin scope)
예약 상태코드 / Reservation Status Codes HB00600R = 예약확정 / Confirmed  ·  HB00600X = 예약취소 / Cancelled
위약금·금액 규칙 / Amount Rules SELL_AMT(API 6) = 입금가(PMS 원가) 전송 — 마진 미포함.
위약금율 = API 10 DLFT_APLY_AMT ÷ SELL_AMT(입금가). 고객 청구 위약금 = 위약금율 × 우리 DB 판매가(소수점 첫째자리 반올림). PMS 납부액은 DLFT_APLY_AMT 원금 그대로이며, 차액(마진 비례분)은 우리가 수취합니다. ※ 실제 응답 필드명은 DLFT_APLY_AMT입니다 (원본 문서 DFLT_APLY_AMT는 오타).
SELL_AMT (API 6) is sent as the net/base price (no margin). Penalty rate = API 10 DLFT_APLY_AMT ÷ SELL_AMT; customer-charged penalty = rate × our sale price (rounded to 1 decimal). PMS receives the original DLFT_APLY_AMT; the difference is retained by us. Note the real field name is DLFT_APLY_AMT (the doc's DFLT_APLY_AMT is a typo).
7. 숙소 식별 체계 / Property ID System

PMS는 BSDV_ID(건물그룹) + SLST_ID(동/타워)로 숙소를 식별합니다. 어드민 숙소 레코드와 PMS SLST_ID 간 초기 매핑 설정이 필요합니다.
PMS identifies properties by BSDV_ID (building group) + SLST_ID (tower/unit). Initial mapping between admin property records and PMS SLST_ID is required.

8. 주요 확정·미결 항목 / Key Decisions & Open Items
미결 · 수기 상품 취소정책 형식 수기 관리 상품의 취소정책이 정책서 = 7구간(동적 구간) vs 프로토타입 v0.6 = 단순 2택으로 상충합니다. 최종 사양 확정 필요 (5절 참조).
Manual-mode cancellation format conflicts: policy doc says 7-segment/dynamic, prototype v0.6 says 2-option. Final spec to be confirmed (see §5).
확정 · TIME_CD 6 B타입(일반 숙박 15:00 입실 ~ 11:00 퇴실) 단일 운영으로 확정되었습니다. A타입(데이트룸 12:00~08:00)·C타입(레이트 18:00~14:00)은 사용하지 않으며, API 13은 미사용입니다. API 5 응답의 TIME_CD가 null이면 B타입으로 처리합니다. (추후 사업부 판단에 따라 변경될 수 있음)
Confirmed: standard (B) type only — check-in 15:00 / check-out 11:00. Types A/C are not used and API 13 is not used. A null TIME_CD in the API 5 response is treated as type B. (May change later per business decision.)

개발자 주의사항
Developer Notes

1
인증 구현 / Auth
모든 PMS API 호출에 HTTP Basic Auth + HMAC-SHA1 서명이 필요합니다. 인증 키는 하이원으로부터 별도 전달받습니다.
All PMS API calls require HTTP Basic Auth + HMAC-SHA1. Auth keys will be provided by High1 separately.
2
모드 불변 / Immutable Mode
연동 모드는 UI뿐 아니라 DB 레벨에서도 변경 불가로 처리하는 것을 권장합니다. mode 컬럼에 IMMUTABLE 제약 또는 업데이트 차단 트리거를 적용하세요.
Enforce mode immutability at the DB level, not only in UI. Apply an IMMUTABLE constraint or update-blocking trigger on the mode column.
3
PMS 오류 처리 / Error Handling
PMS API 호출 실패 시 어드민이 동작 불능이 되지 않도록 fallback UI를 구현합니다. 재고·요금 조회 실패 → "PMS 연동 오류 — 동기화 버튼으로 재시도" 메시지 표시.
Implement fallback UI to prevent admin lockout on PMS failure. On inventory fetch failure → show "PMS sync error — please retry via Sync button".
4
결제 범위 외 / Payment Out of Scope
API 11(카드 정보 등록), 환불 처리는 어드민 범위 외입니다. 고객 화면(프런트) 또는 별도 결제 시스템에서 처리합니다.
API 11 (card info registration) and refund execution are out of admin scope. Handled by the customer-facing front or a separate payment system.
5
BOOKING_ID
예약 요청(API 6) 시 BOOKING_ID(업체 예약번호)는 OTA 어드민 측에서 생성하는 고유 번호입니다. 중복 없는 고유 ID 생성 로직이 필요합니다.
BOOKING_ID in API 6 is a unique reservation number generated by the OTA admin side. A unique ID generation mechanism is required.
6
TIME_CD — B타입 단일 확정 / Type B only
B타입(15:00~11:00) 단일 운영 확정으로 API 13은 구현하지 않습니다. API 5의 TIME_CD가 null이면 B타입으로 처리하세요. (추후 변경 가능)
Standard (B) type only — do not implement API 13. Treat a null TIME_CD from API 5 as type B. (May change later.)
7
테스트 환경 / Test Env
개발 BASE URL 테스트 가능 여부 및 테스트용 인증 키 확인이 필요합니다. PMS 업체 확인 사항은 별도 질문 목록 문서를 참조하세요.
Confirm availability of development BASE URL for testing and test auth keys. See the separate vendor question list for PMS-specific queries.
