⭳ 엑셀 다운로드 6
기준: v0.8 4절 · 5절 · 7절 · 9절 · 12.5절
· 쿠폰 상태 3종: SOLD(판매완료·현장 사용가능, = "미사용") → USED(사용완료), 주문취소 시 CANCELED. 쿠폰번호는 구매 시점에 생성되므로(정책서 2.2절) 발급현황에는 판매 전(AVAILABLE) 상태가 없습니다.
· 상태 변경은 하이원 POS/KIOSK가 우리 서버로 호출하는 사용(use)·사용취소(cancel) API 또는 주문 취소(S15)로 발생. 이 화면은 조회 중심.
· 취소는 두 가지로만 처리합니다. ① 사용취소(cancel API) = 현장 실수로 되돌릴 때, USED → SOLD 원복. ② 주문취소(S15) = 구매 자체 취소, SOLD → CANCELED. 별도의 VOID(무효화)는 운영하지 않습니다(정책서 §9 · M-05 "VOID 미운영").
· CANCELED 쿠폰번호는 재사용 가능, USED 쿠폰번호는 재사용 불가(정책서 2.4절).
· 쿠폰 1개 = 1영업장. 리프트권+장비렌탈처럼 여러 권종을 함께 사면 권종마다 별도 쿠폰번호(바코드)가 발급됩니다(정책서 7절).
쿠폰 API 연동 정보 7
쿠폰 조회·사용·사용취소는 하이원(POS/KIOSK)이 우리(OTA) 서버 주소를 호출하는 구조입니다. 즉, 우리가 API 서버(외부와 데이터를 주고받는 통로)를 만들고, 하이원이 그 주소를 불러 씁니다. 인증(로그인) 없음. 하이원이 부를 때마다 응답은 항상 BARCODE(쿠폰번호) + RESULT(결과코드) + MSG(메시지) 3개 값으로 돌려줍니다.

화면 주석

1
통계 카드
발급 총수 / 사용완료(USED) / 미사용(SOLD) 3개를 상단에 집계. 현재 필터 조건 반영. "미사용" = SOLD(판매완료·아직 현장에서 안 쓴 쿠폰).
2
필터/검색
구매일 범위 · 쿠폰상태(SOLD/USED/CANCELED) · 상품 + 통합검색(쿠폰번호/주문번호/구매자명).
3
쿠폰번호
고객 발급 12자리 코드(쿠폰ID 3 + 레벨 1 + 일련번호 6 + 난수 2). 예: OAT1 00014 57. High1 POS가 이 번호로 조회/사용.
4
연결 주문번호
이 쿠폰이 발급된 S15 주문. 클릭 시 해당 주문 상세로 이동. 1주문 = N장 쿠폰.
쿠폰 1개 = 1영업장(권종). 리프트권 + 장비렌탈처럼 여러 권종을 한 번에 구매하면 권종마다 별도 쿠폰번호(바코드)가 발급됩니다(정책서 7절).
5
쿠폰 상태
쿠폰 상태 흐름: 구매 → SOLD → 사용(use) → USED. 현장 실수로 되돌릴 때 사용취소(cancel) → USED에서 SOLD로 복원. 주문취소(S15) 시 SOLD → CANCELED. 쿠폰번호는 구매 시점에 생기므로(정책서 2.2절) 판매 전(AVAILABLE) 상태는 발급현황에 나타나지 않음.
상태 변경은 하이원 POS/KIOSK가 부르는 사용(use)·사용취소(cancel) API 또는 주문 취소(S15)로 발생. 이 화면에서 직접 상태 변경은 없음(조회 중심).
취소는 사용취소(USED→SOLD 원복) 또는 주문취소(SOLD→CANCELED)로만 처리하며, 별도의 VOID(무효화)는 운영하지 않음(정책서 §9 · M-05 "VOID 미운영").
CANCELED 쿠폰번호는 재사용 가능, USED 쿠폰번호는 재사용 불가(정책서 2.4절).
6
엑셀 다운로드
현재 필터 조건 기준 전체 쿠폰 목록 다운로드.
7
쿠폰 API 연동 정보
쿠폰 조회·사용·사용취소 API는 하이원(POS/KIOSK)이 우리(OTA) 서버 주소를 호출하는 구조입니다. 우리가 API 서버를 만들고 하이원이 그 주소(hiww_ent_search / use / usecancel .jsp)를 불러 씁니다. 인증(로그인) 없음. 응답은 항상 BARCODE + RESULT + MSG 3개 값.
응답코드: DBOK=성공 / DBER01=자릿수 오류 / DBER02=미존재 / DBER03=이미 사용됨 / DBER04=취소됨. DBER31·32(유효기간 이전·경과)는 날짜 유효성 체크를 만들지 않아 발생하지 않음(정책서 4.2·4.3절).
