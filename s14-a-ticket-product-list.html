티켓 상품 S14-A
기준: 프로토타입 admin v0.7.31
· 카드 = 상품, 카드 안 행 = 레벨(대인/소인). 상품 1개(쿠폰ID 연결) 아래 레벨이 하위 표로 펼쳐집니다. 레벨은 S13 쿠폰 스펙에서 자동 로드됩니다.
· 레벨 구조 2가지 — ① 2레벨(대인 LV.1 · 소인 LV.2) ② 1레벨(대인 전용, 예: 곤돌라). ※ 프로토타입은 상품당 대인·소인 2레벨(또는 대인 1레벨)만 사용.
· 노출 = 스펙 ON AND 상품 노출 ON AND 판매중 (3개 모두 충족해야 프런트 노출). 하나라도 아니면 미노출.
· 노출 제어는 상품 단위 토글 1개뿐(레벨별 개별 on/off 없음). 연결 스펙 OFF → 강제 미노출 🔒(상품 토글 잠김). 판매기간 종료 → 자동 미노출.
· 마진은 S11 마진관리(쿠폰ID 단위)에서 관리 → 이 화면은 판매가로 표시만. 판매가 = 입금가 + 마진(소수점 버림). 입금가(원가)는 고객 미노출.
· 날짜 방식은 오픈형이 기본·우선. 날짜지정형은 기능만 유지·현재 미사용.
· 상품명 등 텍스트는 EN(필수) / ZH(선택) 입력. 외국인 전용 사이트라 국문(KO)은 사용하지 않음.

→ 개발 반영 시점에 화면 갱신 예정. (본 화면은 프로토타입 admin v0.7.31 기준으로 작성)

화면 주석

1
총 상품 수
등록된 티켓 상품(쿠폰ID 연결)의 총 개수입니다. 프로토타입은 상품 목록 상단에 개수만 표시하며, 별도 검색·필터 UI는 없습니다(카드 정렬은 최종수정일 최신순).
2
+ 상품 등록
S14-B 상품 등록 폼으로 이동. 연결할 스펙(S13)을 선택해 새 상품을 만듭니다.
등록 가능한 스펙이 없으면(S13 미등록) "먼저 쿠폰 스펙을 등록하세요" 알럿 후 이동 차단. 스펙 선행 원칙.
3
쿠폰ID (카드 헤더 코드)
이 상품이 연결한 S13 쿠폰 스펙의 ID(coupon_id)입니다. 값 형식: 3자리 코드 예) SVA·GDO·DBO. 데이터 성격: 상품 생성 시 스펙 선택으로 확정(수정 불가), 읽기전용 표시. 입금가·레벨·사용기간의 원천이 이 스펙입니다.
4
상품명 (EN 필수 / ZH 선택)
고객에게 보이는 상품 이름. 값 형식: 영문 타이틀 + (회색) 중문 병기. 데이터 성격: 어드민 직접입력(S14-B). 영어(EN)는 필수, 중국어(ZH)는 선택(비우면 EN 대체 표시). 국문(KO)은 미사용.
→ 프런트: 티켓 상품 카드·상세 타이틀
5
판매상태 배지 (자동 계산)
판매기간(판매시작~판매종료일) 기준으로 시스템이 자동 판정합니다. 값 3종:
배지조건
판매중오늘이 판매기간 이내
판매전오늘 < 판매시작일
판매종료오늘 > 판매종료일 (자정 경과 시 자동 미노출)
데이터 성격: 자동 계산(어드민 편집 불가). 판매기간 자체는 S14-B에서 관리자가 입력.
6
노출 배지 + 노출/미노출 토글 (상품 단위)
상품(쿠폰ID) 단위의 노출 상태를 나타냅니다. 레벨별 개별 on/off는 없습니다. 배지 3종:
배지의미조건
노출중프런트 노출스펙 ON AND 상품 노출 ON AND 판매중
미노출미노출상품 노출 OFF 또는 판매종료
강제 미노출 🔒스펙 잠김연결 스펙(S13) OFF (Cascade)
[노출]/[미노출] 버튼: 상품 노출 토글(visibility Y/N). 버튼 라벨은 현재 상태의 반대 동작(노출중이면 "미노출", 미노출이면 "노출").
강제 미노출 🔒 상태에서는 토글 버튼이 비활성(disabled) — 연결 스펙이 OFF라 제어 불가. S13에서 스펙을 ON하면 다시 상품 토글로 제어 가능.
→ 프런트: 3개 조건(스펙·상품·판매중) 모두 충족 시에만 상품 카드 노출
7
수정 · 삭제
수정: S14-B 편집 폼으로 이동. 삭제: 상품 삭제(예약/주문 이력 있는 경우 처리 정책은 예약관리 기획 시 확정). 스펙과 달리 상품은 우리 판매 단위라 직접 수정·삭제 가능.
8
[표] 레벨
한 상품 안의 판매 옵션 단위. 값 형식: LV.N + 레벨명 예) LV.1 대인 / LV.2 소인. 데이터 성격: S13 쿠폰 스펙에서 자동 로드(읽기전용).
레벨 구조 2가지: 2레벨(대인 LV.1·소인 LV.2) / 1레벨(대인 전용, 예: 곤돌라 — 소인 행 없음). ※ 성수기/비수기 4레벨은 정책 확장(프로토타입 미구현).
→ 프런트: 상품 상세에서 대인/소인 수량 선택
9
[표] 쿠폰명
레벨별 쿠폰 표시명(coupon_name). 값 형식: 기본명(대인/소인) 예) "스키 리프트 종일권(대인)". 데이터 성격: S13 스펙에서 자동 로드(읽기전용). High1 제공 쿠폰 스펙의 명칭이며 상품명(EN/ZH)과 별개.
10
[표] 카테고리
상품의 분류 경로(최대 2뎁스). 값 형식: 1뎁스 또는 1뎁스 › 2뎁스 예) "스키 › 리프트권" / "워터파크"(2뎁스 없음). 데이터 성격: S14-B에서 선택(S17 카테고리 트리 기준). 권종(종일권·4시간권 등)은 뎁스가 아니라 상품명·쿠폰명에서 구분.
→ 프런트: 카테고리 네비게이션·필터 분류
11
[표] 판매기간
우리 홈페이지에서 판매 가능한 기간(판매시작일 ~ 판매종료일). 값 형식: YYYY-MM-DD ~ YYYY-MM-DD(미설정 시 "즉시"·"무기한"·"상시"). 데이터 성격: S14-B에서 관리자 입력(상품 단위, 모든 레벨 공통). High1 제공 사용기간과 별개. 판매종료일 자정 경과 시 자동 미노출.
12
[표] 사용기간
현장 사용(입장) 가능 기간. 값 형식: use_start_date ~ use_end_date. 데이터 성격: S13 스펙에서 자동 로드(레벨별), 읽기전용. High1이 정한 실제 이용 가능 기간이며 판매기간(11)과 다름.
13
[표] 입금가 (원가 · 고객 미노출)
우리가 High1에 실제로 내는 원가. 값 형식: NN,NNN원. 레벨별로 다름(대인 > 소인 일반적). 데이터 성격: S13 스펙에서 자동 로드(읽기전용). 고객에게 절대 미노출, 판매가 계산의 출발점.
14
[표] 적용 마진 (S11에서 온 값 · 표시만)
입금가에 얹는 이익. 값 형식: 율은 10%, 정액은 +4,000원. 데이터 성격: S11 마진관리(쿠폰ID 단위, 카테고리 마스터+오버라이드)에서 결정 → 이 화면은 표시만(편집 불가). 같은 상품의 모든 레벨에 동일 적용(쿠폰ID 단위).
양수(+)=마크업, 음수(−)=할인. 계산 결과 소수점은 무조건 버림(floor).
15
[표] 판매가 (= 입금가 + 마진)
고객에게 보이는 최종 가격. 값 형식: NN,NNN원(강조 표시). 데이터 성격: 자동 계산(입금가+마진, floor). 레벨별로 각각 계산. 예) 65,000 × 10% = 71,500 / 40,000 + 4,000 = 44,000.
→ 프런트: 상품 카드·상세 가격
16
강제 미노출 🔒 (Cascade)
연결한 S13 쿠폰 스펙이 OFF이면 이 상품은 강제로 미노출되고, 노출 토글 버튼이 비활성(잠김)됩니다. 상품 개별 제어 불가.
해제 방법: S13 쿠폰 스펙 관리에서 해당 스펙을 다시 ON → 상품 토글로 제어 복귀.
