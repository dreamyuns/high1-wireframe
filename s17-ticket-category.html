S17 카테고리/컨텐츠 관리 — 목록 — 티켓관리 GNB · LNB 최상단

화면 주석

0
공통정책 — 위치 이동 + 콘텐츠 소유(A안)
이 화면은 공통관리 → 티켓관리 GNB로 이동했고, 티켓관리 LNB 최상단에 위치합니다(프로토타입 기준). 명칭도 "티켓 카테고리관리" → "카테고리/컨텐츠 관리"로 바뀌었습니다.
정책서 v0.13 §12.1·§12.6 원문은 아직 "공통관리"로 되어 있어, 정책서 동기화 필요(플래그). 화면기획서는 프로토타입을 기준으로 선반영합니다.
1
카드형 구조 — 1뎁스 카드 / 2뎁스 행
카드 하나 = 1뎁스 카테고리(예: Ski·Water Park). 카드 안 표의 행 하나 = 2뎁스 상품유형(예: Lift Pass·Equipment Rental). 최대 2뎁스입니다.
2뎁스가 없는 1뎁스(워터파크·식사권·곤돌라)는 카드 본문에 "하위 없음" 안내만 표시됩니다.
→ 프런트: 카테고리 네비게이션·필터, 상품 카드 분류 라벨
2
직접 등록 (추가 · 수정 / 삭제 없음)
[+ 1뎁스 카테고리 추가]는 최상위 카테고리를 새로 만듭니다. 각 1뎁스 카드의 [+ 하위(2뎁스) 추가]는 그 아래 상품유형을 만듭니다. [수정]은 표시명(EN/ZH)·관리명·순서를 바꿉니다. 모두 등록 모달(CN5)이 열립니다.
삭제 버튼은 없습니다(추가·수정만). 2뎁스가 이미 최대 뎁스이므로 2뎁스 행에는 "+ 하위 추가"가 없습니다. "연결상품 N"은 해당 카테고리에 묶인 S14 상품 수(참고용).
3
[콘텐츠] 버튼 — 리프(말단) 뎁스에만
프런트 브릿지에 보여줄 콘텐츠(히어로·개요·상세설명·이용안내·정책·위치)를 편집하는 화면(S17-B)으로 이동합니다.
콘텐츠는 말단(리프) 뎁스가 소유합니다: 2뎁스가 있으면 각 2뎁스 행에, 2뎁스가 없으면 그 1뎁스 카드 헤더에 [콘텐츠] 버튼이 붙습니다. (2뎁스를 가진 1뎁스 자체에는 콘텐츠 버튼이 없음)
상품(S14)은 콘텐츠를 갖지 않고 썸네일만 소유합니다. 상세·안내·정책 등은 카테고리 단위 공통(중복 등록 방지). (정책서 v0.13 §12.6)
4
표시명 EN / ZH + S13 검증 기준
외국인 전용이라 KO는 표시명이 아니라 내부 관리명(CSV 매칭용)입니다. 고객 표시명은 EN(필수)/ZH(선택). ZH 미입력 시 EN 대체.
여기 등록한 카테고리/상품유형 이름이 S13 업로드 검증 기준입니다. S13 CSV의 값과 정확히 일치해야 하며, 다르면 그 행은 업로드 실패(12.2절).
5
카테고리 등록·수정 모달
상위 카테고리(1뎁스=최상위 고정 / 2뎁스=상위 1뎁스명) · 관리명 KO(내부·CSV) · 카테고리명 EN(필수)/ZH(선택) · 노출 순서를 입력해 저장합니다. EN 미입력 시 저장 불가.
삭제 없음. 수정 모드는 기존 값이 채워지고, 신규 등록 모드는 빈 값으로 시작합니다.
