03 객실 식별 체계 (RM_TYP_CD)
객실 식별자 이원화 — 내부 객실코드(RM-####) vs PMS코드(RM_TYP_CD) 확정
객실은 두 종류의 코드를 갖는다. 역할이 다르므로 혼동하지 않도록 구분한다.
코드발급 주체역할화면 표시
RM-#### (객실코드)우리 시스템 자동채번내부 객실 식별자 (1객실 = 1코드). 상품연결·예약·이력 참조 키S03 목록: 객실명 아래 병기 / S04: 읽기전용 필드
RM_TYP_CD (PMS코드)PMS 동기화요금·재고·마진 기준 키 (업장 내 고유, 전역 고유 아님)S03 목록: PMS코드 컬럼 / S04: 별도 필드
RM-#### ≠ RM_TYP_CD. 하나의 RM_TYP_CD(예: STD)에 여러 객실(RM-0001·RM-0007…)이 매핑될 수 있다.
S03 객실 목록 맨 앞 No.(순번)은 정렬·필터에 따라 바뀌는 화면 표시용 번호이며 식별자가 아니다.
RM_TYP_CD 범위 확정
RM_TYP_CD는 업장(SLST_ID) 단위 고유. 전역(글로벌) 고유가 아님.
동일한 RM_TYP_CD 값(예: STD)이 서로 다른 SLST_ID에 중복 존재 가능.
객실 식별 복합 키: SLST_ID + RM_TYP_CD
수준필드설명예시
시설 그룹BSDV_ID건물 그룹 단위01 (그랜드 호텔)
업장SLST_ID동·타워 단위1101 (메인타워)
객실유형RM_TYP_CD업장 내 고유STD, DLX, STT
URL·캐시 기준 복합 키 = SLST_ID + RM_TYP_CD. 예: /1101/rooms/STD
ITM_ID 구조 확정
PMS API 3 응답의 ITM_ID = HB + SLST_ID + RM_TYP_CD + 채널코드
구성요소설명예시
HB시스템 프리픽스 (고정)HB
SLST_ID업장구분코드 4자리1101
RM_TYP_CD객실유형코드STD
채널코드OTA 채널 식별자 3자리054
예: HB1101STD054 = 메인타워(1101) 스탠다드(STD) OTA채널(054)
RM_TYP_NM · RM_TYP_INFO 처리
RM_TYP_NM (객실명): PMS가 한글명으로 제공. S04 "객실명" 필드 기본값으로 pre-fill.
관리자가 S04에서 별도 입력 시 해당 값을 우선 사용(오버라이드). 미입력 시 PMS 제공명 사용.

RM_TYP_INFO (객실안내): PMS가 자유 텍스트 형식으로 제공 (예: "킹 사이즈 침대 1개, 소파베드 1개").
구조화된 침대구성 UI에 직접 매핑 불가. PMS 불러오기 시 S04 객실안내(guide_html) 필드에 텍스트로 pre-fill.
관리자가 직접 편집 가능. S04 침대구성 필드는 관리자가 원하는 경우 별도 선택 입력.
S04 침대구성은 선택 입력 — PMS 자동 매핑 없음. 관리자 직접 입력 전용.
S04 객실명은 선택 입력 — 미입력 시 RM_TYP_NM 사용.

05 마진 계산 규칙
2단계 계층 구조 — 일자별 마진 v0.9.6 변경
마진은 일자(날짜)별로 관리한다. 요금 동기화(입금가 갱신)와 독립 운영되어 마진은 보존되고 판매가만 재계산된다.
1단계 — 객실 타입 마진 마스터 (공통관리 > 마진관리): 객실 타입(RM_TYP_CD) 단위 기본 마진. 각 상품의 일자별 마진 디폴트로 주입. 마스터 미설정 시 전역 기본(마진금액 30,000).
2단계 — 상품 일자별 마진 (S06 재고·요금 탭): 관리자가 날짜별 마진율/금액을 개별 조정(오버라이드). 미조정 일자는 마스터 상속.
마스터 변경 시 개별 조정하지 않은(상속) 일자의 판매가는 즉시 최신 마스터로 재계산. 개별 조정한 일자만 유지. 이력 관리 필수.
v0.9.6: 기존 "시설(Place) 단위 마스터 + 상품 단위 개별" → "객실 타입 마스터 + 상품 일자별"로 재정의 (프로토타입 반영).
계산 공식
마진 유형입력 범위계산식
마진율 (%) -49% ~ +100% (정수만) 판매가 = floor(입금가 × (1 + 마진율 / 100))
마진금액 (원) 제한 없음 (음수 허용) 판매가 = 입금가 + 마진금액
마진 없음 — 판매가 = 입금가
소수점 발생 시 무조건 버림(floor). 반올림 아님.
API 6 SELL_AMT 전송값 확정
API 6(예약 요청) SELL_AMT 필드에는 입금가(PMS 원가)를 전송한다.
OTA 마진은 우리 DB에만 저장하며, PMS에는 전달하지 않는다.
항목API 6 전송값저장 위치
SELL_AMT입금가 (PMS 원가 그대로)PMS 전달
판매가 (입금가 + 마진)전송 안 함우리 DB만
마진전송 안 함우리 DB만
API 10(위약 적용) 응답의 SELL_AMT도 우리가 보낸 입금가가 그대로 반환됨. API 샘플 실측 확인.
위약금율 = DLFT_APLY_AMT ÷ SELL_AMT(입금가). 고객 청구 위약금 = 위약금율 × 판매가.
주의: API 10 응답 필드명 오타 — DFLT_APLY_AMT가 아닌 DLFT_APLY_AMT로 반환됨.

09 추가요금 안내 (정보 노출성)
v0.2 — 객실 부가요금 → 숙소 추가요금 안내로 이관 확정
기존 객실(S04)의 '부가요금 설정'(인원 추가요금·엑스트라베드, ON_SITE 현장 결제) 을 폐기하고, 숙소(S02-4 안내·정책)의 '추가요금 안내(extra_fee_notes)' 로 이관한다.
성격이 결제 연동 필드 → 정보 노출성 안내 텍스트로 바뀐다. 여기 입력한 금액은 실제 계산·청구에 사용되지 않으며, 고객에게 "이런 추가요금이 있다"는 안내 목적만 갖는다.
입력 단위: 숙소(Place). 한 줄에 하나씩 자유 텍스트. [+ 항목 추가]/[삭제]로 행 관리. 저장 필드 extra_fee_notes[] { en(필수), zh(선택) }.
다국어: 각 행 EN 필수(미입력 시 저장 불가) · ZH 선택(미입력 시 EN 대체). KO 입력칸 없음.
결제 개념(ON_SITE / AT_BOOKING) 완전 폐기. 인원 추가요금·엑스트라베드의 결제·계산 로직 없음. 프런트 정책정보 탭 '추가요금' 블록에 목록(•)으로만 표시(빈 배열이면 블록 숨김).

12 객실 등록 선행 원칙 & 노출 연동 정책
객실 등록 선행 원칙 확정
상품 등록 전 반드시 객실이 먼저 등록되어야 한다. 수기 상품 포함 예외 없음.
객실 등록 = 객실유형 1개 이상 포함하여 저장 완료된 상태 (저장 시 유효성 검사).
PMS 불러오기 시 연결 객실 없으면 알럿 + 저장 불가. S04에서 먼저 객실 등록 필요.

상품이 프런트에 노출되려면 아래 두 조건을 모두 충족해야 한다.
조건제어 주체
① 연결된 객실 노출여부 = SHOW관리자 (S04)
② 상품 노출여부 = SHOW관리자 (S06-A)
노출 연동(Cascade) 체계 — 객실 1 : 상품 N 확정
객실 1개에 상품 N개가 연결되는 구조이므로, 객실 상태 변경 시 하위 상품 전체에 연동 적용된다.
객실 상태연결 상품 처리관리자 개입 가능 여부

리노베이션·점검 등으로 객실을 HIDE 전환 시 해당 객실의 모든 상품이 프런트에서 즉시 미노출됨. 전환 전 영향 범위 확인 필요.

14 최저가 노출 정책 (추천 카드)
가격 기준 확정
추천 카드에 표시되는 최저가는 마진 포함 판매가 기준이다. 입금가(원가)는 고객에게 노출하지 않는다.
판매가 = 입금가 + 마진 적용 결과(소수점 버림). 마진 계산 규칙은 섹션 05 참조.
Sold Out 날짜 제외 확정
재고가 0인 날짜는 최저가 산출 대상에서 제외한다. 재고가 1 이상인 날짜 중 가장 낮은 판매가를 최저가로 사용한다.
기준 재고 필드: AVLB_RM_CNT (API 4 잔여 재고). 0이면 해당 날짜 제외.
복수 상품 기준 확정
하나의 객실에 여러 상품(패키지)이 연결되어 있을 경우, 연결된 상품 전체 중 가장 낮은 판매가를 최저가로 자동 선택한다. 대표 상품 수동 지정 없음.
예시상품판매가최저가 선택
디럭스 더블기본 패키지110,000원✅ 선택됨
조식포함 패키지143,000원—
디너포함 패키지176,000원—
배치 처리 방식 협의 후 변경 가능
최저가는 매번 실시간으로 계산하지 않고, 정기 배치를 통해 사전 산출 후 room.price_min_batch 컬럼에 저장한다. 프런트는 이 값을 읽어 표시한다.

배치는 요금 동기화(API 3) 실행 시 함께 갱신하는 방향으로 검토 중이며, 배치 실패 시의 fallback(마지막 배치값 유지 vs 실시간 계산)은 개발 협의 시 결정한다.
배치 주기와 실패 처리 방식은 개발사와 협의 후 확정한다. 실시간 계산 대비 배치 방식은 DB 부하 감소 목적이나, 가격 갱신 지연이 발생할 수 있다.
날짜 범위 초안 — 협의 후 변경 가능
최저가 산출 대상 날짜 범위의 초안은 오늘 ~ 30일 이내로 설정한다. 재고 > 0인 날짜만 포함.
항목초안값협의 포인트
조회 범위 오늘 ~ 30일 이내 성수기·비수기 패턴에 따라 60일 또는 90일로 확대 검토 가능
범위 내 재고 0 전용 Sold Out 처리 (최저가 미표시 또는 "-") 범위 내 전 날짜 재고 0인 경우 표시 방식 미확정
날짜 범위 확정 후 room.price_min_batch 배치 로직 구현 시 반영. 변경 시 이 섹션과 REF-7 callout 13 동시 업데이트.

05 Margin Calculation Rules
Two-Tier Hierarchy — Per-Date Margin Changed in v0.9.6
Margin is managed per date, operating independently of rate sync (base-price updates) — margins are preserved and only sell prices recalculate.
Tier 1 — Room-Type Margin Master (Common > Margin Mgmt): Default margin per room type (RM_TYP_CD), injected as each product's per-date margin default. Falls back to global default (amount 30,000) if unset.
Tier 2 — Product Per-Date Margin (S06 Stock·Rate tab): Operator overrides margin rate/amount by date; unedited dates inherit the master.
On master change, inherited (unedited) dates recalculate to the latest master; only manually edited dates are retained. Change history required.
v0.9.6: Redefined from "Property-level master + product-level individual" to "Room-type master + product per-date" (prototype reflection).
Calculation Formula
Margin TypeInput RangeFormula
Margin Rate (%) -49% to +100% (integers only) Sell Price = floor(Base × (1 + Rate / 100))
Fixed Margin (KRW) No limit (negatives allowed) Sell Price = Base Price + Fixed Amount
No Margin — Sell Price = Base Price
Decimal results are always floored (truncated), never rounded.

09 Extra Fee Notes (Informational)
v0.2 — Moved from Room extra charges to Property extra fee notes Confirmed
The room-level "Extra Charge Settings" (per-person surcharge, extra bed; ON_SITE payment) in S04 is discontinued and moved to the property-level "Extra Fee Notes (extra_fee_notes)" in S02-4 (Guide & Policy).

Payment concept (ON_SITE / AT_BOOKING) fully discontinued. No settlement/calculation logic for per-person surcharge or extra bed. Rendered only as a bulleted list in the front Policy tab "Extra Fees" block (hidden if the array is empty).

14 Lowest Price Display Policy (Recommendation Cards)
Price Basis Confirmed
The lowest price shown on recommendation cards is based on the sell price (margin-inclusive). The base price (cost) is never displayed to customers.
Sell price = Base price + margin (floor on decimals). See Section 05 for margin calculation rules.
Exclude Sold-Out Dates Confirmed
Dates with zero stock are excluded from the lowest-price calculation. The lowest sell price among dates with stock ≥ 1 is used.
Stock field: AVLB_RM_CNT (API 4 available stock). Excluded if = 0.
Multi-Product Rule Confirmed
When a room has multiple linked products (packages), the lowest sell price across all linked products is automatically selected. No manual "representative product" designation.
