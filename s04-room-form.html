객실코드 (자동 채번)
RM-#### 형식으로 자동 생성된다. 수정 화면에서는 읽기 전용으로 표시된다.
→ 프런트: 미노출 (내부 식별자)
2
객실유형·특징 (멀티칩) — 저장 필수 조건
마스터 데이터(공통관리 > 객실유형관리)에서 불러온 선택지로 구성된다. 객실유형은 최소 1개 이상 선택 필수(RM-FORM-01). 객실특징은 선택 입력이다.
객실유형을 선택하지 않으면 저장 시 유효성 검사 실패 → 저장 불가.

숙소별 필터: 위 숙소(Place) 선택 시 해당 숙소에 등록된 객실유형(S09-B)만 칩으로 표시됨. 숙소 미선택 또는 해당 숙소에 등록된 객실유형이 없는 경우 칩 목록 비어있음 → 먼저 공통관리 > 객실유형관리에서 해당 숙소 객실유형을 등록해야 함.
→ 프런트: 현재 미노출. 향후 Room Detail 표시 예정.
RM-FORM-01: 객실유형 1개 이상 필수 (저장 시 검사). 상세: policy-decisions.html 섹션 12.
3
침대 구성 (bed_rows) — 선택 입력
bed_type_id + count 쌍의 배열로 저장된다. 침대유형은 마스터(공통관리 > 침대유형)에서 불러온다. '+ 침대 추가'로 복수 침대 유형 구성 가능(예: 킹1 + 싱글1).
선택 입력사항. PMS RM_TYP_INFO는 자유 텍스트 형식이므로 이 필드에 자동 매핑하지 않음. 관리자가 직접 선택·입력. 수기 상품도 동일하게 선택 입력.
→ 프런트: 상품 카드 '침대: 킹 1개' 텍스트 / Room Detail 모달 Information > 침대
4
객실명 (room_name_ko) — 선택 입력
선택 입력사항: 미입력 시 PMS RM_TYP_NM(한글명) 사용. 직접 입력 시 오버라이드. 수기 상품은 직접 입력 필요.

[마스터로 객실명 채우기] 버튼: 폼 어느 단계에서도 클릭 가능. 현재 선택된 침대유형 + 개수 조합 기준으로 자동 생성하여 입력 필드를 즉시 덮어씀 (확인 다이얼로그 없음).
수동으로 입력한 값도 버튼 클릭 시 덮어써진다. 버튼으로 채운 뒤 직접 수정 가능하며, 버튼 재클릭 시 다시 자동 생성값으로 교체된다.
침대 구성 변경 시 버튼을 직접 클릭하지 않으면 필드 자동 갱신 없음.
→ 프런트: 상품 카드 객실명 텍스트 / Room Detail 모달 헤더 대형 텍스트
5
인원 (성인/아동 분리)
기준인원과 최대인원을 각각 성인/아동으로 분리 입력. 총 기준인원 = 성인기준 + 아동기준, 총 최대인원 = 성인최대 + 아동최대 (자동 계산, 읽기 전용 표시).
검증: 총 최대인원 ≥ 총 기준인원, 성인 기준·최대 ≥ 1. 크기는 숫자·소수점만 허용, 선택 입력.
저장 필드: adult_standard_count, child_standard_count, adult_max_count, child_max_count, room_size_sqm.
→ 총 기준/최대인원: 상품 카드 인원 표기 / Room Detail Information > 인원
→ PMS 예약 시: STAY_ADLT_PCNT = 성인 인원, STAY_CHLD_PCNT = 아동 인원으로 분리 전송
→ room_size_sqm: Room Detail Information > 크기 'NN㎡'
RM-FORM-01: 총 최대인원 ≥ 총 기준인원 검증 필수.
6
이미지 업로드
대표 1장 + 추가 최대 9장. 객실은 대표 이미지 필수 검증 없음(기존 데이터 호환성). 2MB 제한.
→ 프런트: 상품 카드 썸네일(2장↑ 시 이전/다음 버튼) / Room Detail 갤러리 그리드(최대 5장 표시)
7
객실 시설 피커 (ROOM 도메인)
ROOM 도메인 카테고리 5개(침실·수면 / 욕실 / 미디어 / 식음료 / 어메니티)가 좌측 목록에 표시된다. 클릭 시 우측에 해당 카테고리 시설 목록 로드.
객실에 적용: 체크 시 facility_ids에 포함. 해제 시 대표 체크도 자동 해제.
대표: "객실에 적용" 체크 상태에서만 활성. 최대 10개. 초과 시 [적용] 차단.
적용된 시설 칩: "카테고리: 시설명" 형식. 대표 시설은 파란 '대표' 뱃지 부착. 저장 시 이 목록 기준으로 기록.
카테고리 전환 시 현재 체크 상태가 state에 자동 병합되어 선택값 유실 없음.
→ facility_ids: Room Detail 모달 ④ 객실시설정보 섹션 카테고리별 목록 / → featured_facility_ids: 상품 카드 하단 시설 칩 나열
8
안내·정책 필드
객실 소개(room_desc): 관리자 직접 입력. PMS RM_TYP_DESC 자동 매핑 없음.
객실 안내(guide_html): 관리자 직접 입력. PMS RM_TYP_INFO 자동 매핑 없음.
객실 정책(policy_html): 금연 안내 등 정책 텍스트. 자유 입력. 비어있으면 해당 섹션 미표시.
→ room_desc: Room Detail 객실안내 섹션 '객실 소개' / → guide_html: Room Detail ③ 객실안내 섹션 / → policy_html: Room Detail ② 객실정책 섹션 상단
9
부가요금 토글
인원추가요금: 기준인원 초과 시 1인당 요금 부과. 엑스트라베드: 베드 추가 가능 여부. 비활성 시 하위 필드 disabled. 반영기준: PMS 추가요금 연동 미지원으로 ON_SITE(현장 결제) 고정.
→ 프런트: Room Detail 모달 ② 객실정책 > 인원추가요금·엑스트라베드 카드 (각각 활성 시에만 표시)
저장 성공 시 → #/rooms/place/:place_id 로 이동. RM-FORM-06
10
변경이력 (A안 — 접이식 섹션)
수정 화면 하단에 위치한 접이식(아코디언) 섹션. 기본 상태는 펼쳐짐. 헤더 클릭 시 접기/펼치기 토글.
이력 기록 조건: [저장] 성공 시 아래 항목 중 변경이 있는 경우에만 새 이력 행 생성.
기록 대상 항목: 객실명, 기준인원(성인·아동), 최대인원(성인·아동), 엑스트라베드 활성여부, 노출여부.
이력 컬럼: 변경일시 / 변경자 / 항목 / 변경 전 / 변경 후 / 사유(선택입력).
신규 등록 시 이력 없음 ("이력이 없습니다" 문구 표시). 최신 이력이 상단.
11
재고관리 탭
객실 상세 화면은 기본정보 / 재고관리 두 탭으로 구성된다.
재고관리 탭: PMS연동 객실은 API 4 RSV_CNT를 기준으로 사용가능 객실 수 표시(읽기전용). 수기관리 객실은 총 재고를 직접 입력하고, 예약 수 차감 후 사용가능 수를 표시.
두 모드 모두 재고 수정 UI의 위치는 이 탭으로 통일. S06-B/C(상품상세)에서는 읽기전용으로만 표시.
→ 재고관리 탭 상세 기획: S04-INV(별도 파일, 향후 작성 예정)

노출 여부
항상 SHOW(Y) / HIDE(N) select 노출. 기본값: HIDE(N) (신규 등록 시 비노출로 시작).
객실유형 필수는 저장 시 유효성 검사로 처리 → 노출여부 필드에 disabled 없음.
노출 Cascade: 객실 HIDE → 연결 상품 전체 강제 N(🔒 배지) + S06-A 경고 박스 표시. 상세: policy-decisions.html 섹션 12.

숙소·객실유형 미선택 상태에서 저장 클릭 시 유효성 검사 실패 → 저장 불가 (기존 CN2 규칙 동일).
