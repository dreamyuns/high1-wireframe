· 스펙은 관리자가 High1 제공 엑셀 → 우리 CSV 템플릿으로 변환 후 업로드한다.
· 데이터(입금가·사용기간 등) 변경은 엑셀 재업로드(덮어쓰기)로만. 어드민 개별 수정·행 삭제 없음.
· 노출 ON/OFF는 운영 토글로 별도 제어(데이터와 분리). 입금가(price)는 High1 납부 원가, 고객 미노출.
· 스펙 OFF 시 연결된 S14 상품 전체 강제 미노출(🔒), ON 시 상품 개별 노출로 복귀. 스펙 제거는 OFF로 대체.

화면 주석

1
CSV 템플릿 다운로드
우리가 정의한 표준 CSV 템플릿(헤더 포함)을 내려받는다. 관리자는 High1 엑셀을 이 템플릿에 맞춰 변환 후 업로드.
2
CSV 업로드
파일 선택 또는 드래그&드롭. 업로드 시 전체 행을 처리한 뒤 결과(성공/실패)를 반환(B안).
컬럼: coupon_id·category·ticket_type·level·level_name·price·use_start_date·use_end_date 필수. product_type은 스키 3뎁스 전용(워터파크는 빈값).
3
CSV 템플릿 양식 (샘플)
업로드할 CSV의 표준 컬럼·예시 데이터. 사용기간은 use_start_date / use_end_date 2컬럼(YYYY-MM-DD). 판매기간 컬럼은 받지 않음.
판매 시작/종료(인쇄기간)는 어드민 미관리 — 정책 v0.2 3.3절. 판매 마감은 S14 커트오프가 담당.
4
업로드 결과 — 요약 + 리포트 다운로드 (B안)
화면에는 성공/실패 건수 요약 한 줄만 표시. 상세 내역(성공 목록 + 실패 라인번호·오류사유)은 화면이 길어지지 않도록 결과 리포트(.txt) 다운로드로 제공.
실패 건은 관리자가 txt 리포트 확인 → 엑셀 수정 후 재업로드. 파일명: upload_result_YYYYMMDD_HHMM.txt
5
쿠폰ID
3자리 코드. 우리 12자리 쿠폰번호의 앞 3자리가 된다. High1이 대행사별로 부여(우리 전용 코드 발급 요청 — 미결 M-04).
6
레벨
LV.1 대인 / LV.2 소인 등. 카테고리에 따라 구성 상이. 동일 쿠폰ID 내 레벨별로 행이 분리됨.
성인/소인 외 레벨(청소년 등) 추가 여부 미확정 (미결 M-08). 유연하게 등록 가능하도록 설계.
7
입금가
High1에 납부하는 원가. 고객에게 노출되지 않음. 판매가 = 입금가 + 마진(S14에서 설정).
→ 프런트: 미노출 (마진 적용된 판매가만 노출)
8
연결상품 수
이 스펙을 사용하는 S14 티켓 상품 개수. 클릭 시 해당 스펙 연결 상품 목록으로 이동(필터). 0이면 아직 상품 미생성.
9
노출 ON/OFF — 운영 토글 (Cascade)
스펙의 운영 노출 스위치(데이터가 아닌 ON/OFF 상태). 관리자가 토글로 즉시 제어.
OFF → 연결된 S14 상품 전체 강제 미노출(🔒, 상품 개별 제어 불가) = "이 쿠폰 종류 판매 일괄 중단". ON → 각 상품 개별 노출여부로 복귀.
데이터(입금가·기간)와 분리: 데이터 변경은 엑셀 재업로드, 노출 ON/OFF는 이 토글로. 스펙 개별 수정·행 삭제는 없음.
10
재업로드 덮어쓰기 확인 (D안)
동일 쿠폰ID+레벨이 이미 존재하면 "N건이 이미 존재합니다. 덮어쓰시겠습니까?" 모달 필수. 관리자가 덮어쓰기/중단 선택. 스펙 데이터 수정의 유일한 경로.
i
판매 유형(얼리/상시/프로모션)
유형별로 쿠폰 코드가 다르므로 어드민에서는 유형별 별도 스펙으로 등록(v0.2 3.5절).
유형 관리 방식(별도 컬럼 vs 별도 스펙) 상세는 미확정 (미결 M-12). 현재는 별도 스펙 등록으로 진행.
