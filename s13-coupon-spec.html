S13 쿠폰 스펙 관리
High1 마케팅팀이 제공하는 쿠폰 스펙 데이터를 CSV로 등록·관리한다. 등록된 스펙은 S14 티켓 상품의 연결 소스가 된다.

쿠폰 스펙 관리 S13
기준: 프로토타입 admin v0.7.31
· 카드 = 쿠폰ID(코드), 카드 안 행 = 레벨(대인/소인). 스펙은 관리자가 High1 제공 엑셀 → CSV 템플릿으로 변환 후 업로드한다.
· 데이터(입금가·사용기간 등) 변경은 CSV 재업로드(덮어쓰기)로만. 어드민 개별 수정 없음.
· 선행 필수업로드 전, CSV의 「카테고리·상품유형」이 S17 티켓 카테고리에 먼저 등록돼 있어야 한다. 미등록 값 행은 실패 처리(사유: 카테고리/상품유형 불일치) → 탭B 업로드 이력에서 라인·사유 확인.
· 노출 ON/OFF는 운영 토글로 별도 제어(데이터와 분리). 스펙 OFF → 연결 S14 상품 전체 강제 미노출 🔒, ON 시 상품 개별 노출로 복귀.
· 스펙 삭제는 조건부 — 연결 상품 0개 AND 발급 쿠폰 0개일 때만 가능(confirm 팝업 필수).
· 입금가는 High1 납부 원가, 고객 미노출. 상품명 등 텍스트는 EN(필수)/ZH(선택), 국문(KO) 미사용.

S11 마진 자동 연동 17
업로드 완료 시 등록된 쿠폰코드가 S11 티켓 마진 목록에 자동 반영됩니다. 신규 쿠폰코드는 마진 미설정(상속) 상태로 행 추가. 기존 쿠폰코드의 카테고리·상품유형이 바뀌고 그 마진이 '상속'이면 새 카테고리 마스터로 재계산 → 결과에 재계산 경고 표시(개별 설정 쿠폰코드는 유지).
확인 팝업(브라우저 confirm) 2종 — 커스텀 모달 아님(프로토타입):
· 재업로드 덮어쓰기 18 — 동일 쿠폰코드+레벨 존재 시 "N건이 이미 존재합니다. 덮어쓰시겠습니까? [취소] 시 중단" confirm. 확인=기존 입금가·사용기간 교체(노출 상태 유지), 취소=업로드 전체 중단.
· 스펙 삭제 — "쿠폰 스펙 XXX를 삭제할까요? (연결 상품·발급 쿠폰 0건일 때만)" confirm. 삭제는 되돌릴 수 없음.
· 노출 토글 — OFF 시 "연결된 티켓 상품이 전부 강제 미노출됩니다" confirm.

화면 주석

1
등록된 스펙 수
현재 등록된 스펙을 쿠폰ID 종수(카드 수)와 레벨행 건수로 표시. 예) "3종 (레벨행 5건)" = 카드 3개, 레벨 합계 5행. 프로토타입은 별도 검색·필터 UI 없음.
2
CSV 템플릿 (다운로드)
표준 CSV 양식(헤더 10개 컬럼 + 예시 1행)을 내려받는다. 관리자는 High1 엑셀을 이 양식에 옮겨 담아 업로드한다. 컬럼 정의는 CN16 표 참고.
3
샘플 스펙 불러오기 (더미) — 프로토타입 전용
프로토타입에서는 실제 파일 업로드 대신 이 버튼이 더미 CSV(4행)를 주입해 검증·덮어쓰기·이력 시연. 실서비스에서는 [파일 선택 → 업로드]로 대체된다.
더미 구성: DBO 대인/소인 2행(기존 존재 → 덮어쓰기 확인 팝업), DC1 곤돌라 1행(신규 성공), DK1 카트레이싱 1행(S17 미등록 → 실패). 결과는 alert + 탭B 이력 기록.
4
쿠폰ID (카드 헤더 코드)
스펙의 3자리 코드(coupon_id). 값 형식: 영문 3자 예) DBO·SVA·GDO. 데이터 성격: CSV 업로드로 등록(읽기전용 표시). 우리 12자리 쿠폰번호의 맨 앞 3자리가 되며 High1이 대행사별 부여(우리 전용 코드 요청 = 미결 M-04).
5
이용권명 (카드 타이틀)
스펙 파일 헤더의 쿠폰 식별명(pass_name). 값 형식: 자유 텍스트 예) "OAT_26성수기_얼리_워터월드(플레이스토리)". 데이터 성격: CSV 업로드로 등록(읽기전용). 쿠폰코드와 1:1 대응, 목록 구분·검색용.
6
메타 (레벨 수 · 연결상품 · 발급)
카드 요약 정보. 값 형식: 레벨 N · 연결상품 N · 발급 N. 데이터 성격: 자동 집계.
· 레벨 N = 카드 안 레벨행 수(대인/소인 등).
· 연결상품 N = 이 스펙을 쓰는 S14 상품 개수(삭제 가능 조건).
· 발급 N = 발급 쿠폰 수 → 현재 0 고정(S16 발급현황 프로토타입 미구현).
7
노출 배지 + 노출 토글 (Cascade)
스펙의 운영 노출 스위치(데이터가 아닌 ON/OFF 상태). 배지 2종: 노출 ON / 노출 OFF 🔒. 버튼은 반대 동작(ON이면 "노출 OFF").
OFF → 연결 S14 상품 전체 강제 미노출(🔒, 상품 개별 제어 불가) = "이 쿠폰 종류 판매 일괄 중단". ON → 각 상품 개별 노출로 복귀. OFF 전환 시 confirm 팝업.
→ 프런트: OFF면 연결 상품 전부 미노출
8
삭제 — 조건부 허용
연결 S14 상품 0개 AND 발급 쿠폰 0개일 때만 삭제 버튼 활성. 못 채우면 비활성(disabled) + 호버 시 "연결 상품 N개 / 발급 쿠폰 N개가 있어 삭제할 수 없습니다".
활성 상태에서 클릭 시 confirm 팝업 → 확인해야 삭제. 삭제는 되돌릴 수 없음(정책 v0.13 12.2절).
9
[표] 레벨
쿠폰코드 내 판매 구분 번호. 값 형식: LV.N + 레벨명 예) LV.1 대인 / LV.2 소인. 데이터 성격: CSV 레벨 컬럼(1/2)에서 로드(읽기전용).
레벨 = 상품(가격) 구분자 역할만. 현장(High1 POS·키오스크)은 쿠폰 스캔 시 해당 레벨 상품 목록만 보여줄 뿐 나이(성인/소인) 검증은 하지 않음(정책 v0.13 2.3절).
10
[표] 쿠폰명
레벨별 쿠폰 표시명(coupon_name). 값 형식: 자유 텍스트 예) "워터월드 종일권_성수기(대인/얼리)". 데이터 성격: CSV 업로드로 로드(읽기전용). High1 제공 명칭이며 S14 상품명(EN/ZH)과 별개.
11
[표] 카테고리
분류 경로(최대 2뎁스). 값 형식: 1뎁스 또는 1뎁스 › 2뎁스 예) "스키 › 리프트권" / "워터파크". 데이터 성격: CSV 카테고리·상품유형에서 로드. 업로드 전 S17에 사전 등록 필수(미등록 시 그 행 실패).
12
[표] 입금가 (원가 · 고객 미노출)
High1에 납부하는 원가. 값 형식: NN,NNN원. 레벨별로 다름. 데이터 성격: CSV 입금가에서 로드(읽기전용). 고객 미노출 — 판매가(=입금가+마진, S11)만 프런트 노출.
→ 프런트: 미노출
13
[표] 할인대상내역
이 쿠폰으로 할인 적용되는 PMS 상품 목록(참고 텍스트). 값 형식: 자유 텍스트 예) "종일권_대인_남_4계절 상품 외 15종". 데이터 성격: CSV 선택 컬럼(빈값 시 "-"). 정산·확인용 참고 정보.
14
[표] 사용기간
현장 사용(입장) 가능 기간. 값 형식: 사용시작일 ~ 사용종료일(YYYY-MM-DD). 데이터 성격: CSV 사용시작일/종료일 2컬럼에서 로드(읽기전용, 레벨별). High1이 정한 실제 이용 기간이며 판매기간과 별개(판매기간은 S14-B 관리).
15
노출 OFF 🔒 (Cascade 강제 미노출)
스펙이 OFF면 카드 전체가 흐리게 표시되고, 연결된 S14 상품이 전부 강제 미노출됩니다(상품 개별 제어 불가). 데이터는 유지되며 노출만 차단.
해제: [노출 ON] 버튼 → confirm → 각 상품 개별 노출로 복귀.
16
CSV 템플릿 컬럼 정의 (10컬럼)
[CSV 템플릿] 버튼이 내려주는 표준 양식. 10개 컬럼 · 순서 준수. 필수 8 / 선택 2(상품유형·할인대상내역). 사용기간은 사용시작일·사용종료일 2컬럼. 판매기간(인쇄기간) 컬럼은 받지 않음(정책 v0.13 3.3절).
17
S11 마진 자동 연동 (§11.8)
업로드 완료 시 등록 쿠폰코드가 S11 티켓 마진 목록에 자동 반영. 신규=행 추가(마진 미설정=상속). 기존=카테고리/상품유형 매핑만 갱신, 마진값 유지.
카테고리·상품유형이 바뀐 쿠폰코드 중 '상속' 항목은 새 마스터로 재계산 → 결과에 재계산 경고. 개별(오버라이드) 쿠폰코드는 유지·경고 제외(정책 v0.13 11.8절·12.2절).

확인 팝업 (브라우저 confirm) — 커스텀 모달 아님
프로토타입은 별도 모달 화면 대신 브라우저 confirm() 팝업으로 처리. 3종: ①재업로드 덮어쓰기 ②스펙 삭제 ③노출 OFF 전환. 각각 확인/취소.
덮어쓰기: 동일 쿠폰코드+레벨 존재 시 → 확인=입금가·사용기간 교체(노출 상태 유지) / 취소=업로드 전체 중단. (스펙 데이터 수정의 유일 경로)

탭B — 업로드 이력 + 인라인 펼침
업로드 시도를 최근 50건 기록(일시·파일명·전체·성공·실패·업로더). 행 클릭 시 아래로 상세 표가 펼쳐짐 — 라인·쿠폰코드·레벨·결과(성공/덮어쓰기/실패)·사유.
실패 사유 예: "카테고리 불일치 (미등록)" / "상품유형 불일치". 관리자는 원인을 확인해 CSV를 고쳐 다시 올린다.

판매 유형(얼리/상시/프로모션)
유형별로 쿠폰 코드가 다르므로 어드민에서는 유형별 별도 스펙으로 등록. 유형 관리 방식(별도 컬럼 vs 별도 스펙)은 미확정(미결 M-12). 현재는 별도 스펙 등록으로 진행.
