API 방향 구분

티켓 쿠폰 조회·사용·취소는 우리(OTA)가 요청하는 것이 아니라, 하이원이 우리 API URL을 호출하는 구조. 우리는 서버를 구현하고 하이원이 그 URL을 호출한다.
전체 플로우
[하이원 마케팅팀] 쿠폰 스펙 전달(엑셀) — 쿠폰ID·레벨별 입금가·적용상품·사용기간 ▼ [우리 어드민] 스펙 등록(S13 CSV) → 상품 생성(S14-B 기본·마진·취소정책 / S14-C 날짜·한도·커트오프) ※ 쿠폰번호 생성은 "구매 시점"(12자리 규칙) — 스펙/상품 단계에선 미발급 ▼ [고객 구매 완료] 쿠폰번호 발급(이메일/마이페이지) → DB 상태: SOLD (발급 시점 생성) 주문 생성(S15) · 쿠폰 발급이력(S16) ▼ [고객 현장] 쿠폰 제시 → High1 POS/KIOSK: GET /search → 우리 서버 DBOK/DBER ▼ High1 POS/KIOSK: GET /use → 우리 서버 SOLD→USED, DBOK → 고객 시설 이용 ▼ [사용취소·현장 실수 복원] High1 POS/KIOSK: GET /cancel → 우리 서버 USED→SOLD 복원, DBOK
2쿠폰번호 구조 및 생성 규칙
쿠폰번호 형식 (12자리)
쿠폰ID(3) + 레벨(1) + 쿠폰 일련번호(6) + 유효번호 난수(2) 예시: AML 1 000001 57 → AML100000157
구성자리수설명
쿠폰 ID3High1이 대행사별 부여하는 식별자(스펙 파일 시트명). 예: DBO, DBR, DC1
레벨1상품 구분 (LV.1=대인, LV.2=소인 등)
쿠폰 일련번호6000001~999999, 우리가 순차 발급
유효번호(난수)2일련번호 패턴 노출 방지용 난수
BARCODE 12자리 확정 (v0.5, M-13 해소): High1 개발팀 Q&A 답변에서 "앞 3자리 쿠폰ID + 1자리 레벨 + 6자리 일련번호 + 2자리 유효번호(난수)"로 확인. 소셜연동 규격서(2018)의 "10자리" 기재는 오기. 12자리가 실제 운용 스펙.
CVX 형식 주의: 참고 엑셀의 CVX-1-XXXXXXXX는 기존 다른 대행사/이전 시스템 형식. 우리는 미사용, 위 12자리 규칙을 따른다.
생성 주체 및 시점
단품: 고객 결제 완료 시 우리 시스템이 12자리 쿠폰번호 자동 생성. High1 사전 등록/통보 불필요, 즉시 고객 전달.
쿠폰번호는 구매(결제 완료) 시점에 생성된다. 스펙 등록·상품 생성 단계에서는 쿠폰번호가 발급되지 않는다. 따라서 발급현황(S16)에는 판매 전(AVAILABLE) 상태의 쿠폰 행이 존재하지 않는다. (5절 참고)
패키지(객실+티켓): 패키지 전용 쿠폰은 일반 쿠폰과 별도 입금가가 존재(패키지 전용 < 일반). 흐름: ① PMS 객실 예약 완료(API 6) → ② 하이원 예약번호(rsv_id) 수령 → ③ 쿠폰번호 12자리 생성 → ④ High1 신규 API에 예약번호↔쿠폰번호 매핑 등록.
패키지 취소 시: OTA는 룸만 PMS 취소(API 7). 패키지 쿠폰 취소/변경은 OTA가 High1에 API 통보 필요(Q7 답변). 단품 취소는 High1 통보 불필요. 패키지 매핑·취소 통보 API 모두 현재 High1 미개발(M-03) — 단품 연동 완료 후 별도 협의.
레벨 구조 / 유니크 규칙
LV.1=대인 / LV.2=소인 / LV.3~8 미사용 예약. 현장에서 성인·소인 별도 확인 없이 레벨별 상품 목록만 표시(Q23 답변). 쿠폰 레벨 = 상품 구분자 역할만 함.
동일 쿠폰ID+레벨 내 유니크. CANCELLED 번호는 재사용 가능, USED 번호는 재사용 불가(Q14 답변).
레벨 구성은 카테고리(스키/워터파크)에 따라 상이. 스펙 파일 수령 후 확정.
(v0.13) 레벨 구조 재정의 — 성수기/비수기 포함. 레벨 = 상품 구분자이며, 구성은 상품 종류에 따라 달라진다. 대인/소인 2레벨 외에, 시즌 내 성수기/비수기까지 구분하는 4레벨 구조도 존재한다.

4API 명세 (우리가 구현할 서버)
개요
API 3개(영업장·상품 구분 없이 통합) · HTTP GET · 인증 없음(Q16 답변) · HTTPS 미확인(M-01, Q17 공란). URL 내 스키리프트권/워터월드 분리 불필요(Q15 답변). 영업장별 별도 endpoint 없음.
약식 URL: 조회 /search?barcode= · 사용 /use?barcode= · 취소 /cancel?barcode=. URL 등록: 우리 서버 URL을 High1 개발팀 담당자에게 전달 → POS/KIOSK 설정값으로 반영(10절).
응답코드 기준 (소셜연동 규격서 2018)
응답 코드(RESULT/MSG)는 소셜연동 규격서(2018) 기준. 규격서 실제 엔드포인트는 hiww_ent_search.jsp / hiww_ent_use.jsp / hiww_ent_usecancel.jsp, 파라미터 BARCODE(대문자), 응답 = BARCODE + RESULT + MSG. 위 /search·/use·/cancel는 설명용 약식 표기.
(1) 조회 — GET /search (hiww_ent_search.jsp?BARCODE=)
RESULTMSG의미우리 처리
DBOKUSE ABLE유효·사용 가능SOLD 확인 후 반환
DBER01BARCODE LENGTH ERR자릿수 오류(12자리 아님)형식 오류
DBER02NO SEARCH BARCODE쿠폰번호 미존재DB에 없는 번호
DBER03USED BARCODE이미 사용됨USED 상태

(2) 사용 — GET /use / (3) 사용취소 — GET /cancel
/use(hiww_ent_use.jsp): SOLD→USED (DBOK/USE OK). 미존재 DBER02·이미 사용 DBER03·취소된 쿠폰 DBER04 오류.
/cancel(hiww_ent_usecancel.jsp): USED→SOLD 복원 (DBOK/USECANCEL OK). 고객이 하이원 결제 후 취소 요청 시 재사용 가능 상태 복원 목적으로 하이원이 호출. 고객 구매 취소(OTA 환불)와 무관(Q7). 시간 제한 없음(Q8). 단품은 High1 별도 통보 불필요, 패키지 쿠폰 취소는 High1 API 통보 필요(2.2절·8절).

5쿠폰 상태 관리
상태 흐름 / 상태 정의 (SOLD / USED / CANCELLED 3종)
쿠폰번호는 구매(결제 완료) 시점에 생성된다(2.2절). 실제 발급된 쿠폰 행은 처음부터 SOLD 상태로 생성되며, 발급현황(S16)에는 판매 전(AVAILABLE) 상태의 쿠폰 행이 존재하지 않는다. AVAILABLE은 "발급 가능한 스펙/재고 개념"일 뿐, 발급된 쿠폰 행의 상태가 아니다.
[구매(결제 완료) 시점에 쿠폰번호 생성] ▼ SOLD ──── 주문 취소(자동/수동) ──→ CANCELLED ← 발급 즉시 초기 상태 │ High1 /use ▼ USED ──── High1 /cancel(사용취소·현장 실수 복원) ──→ SOLD(복원)
상태의미
(AVAILABLE)발급된 쿠폰 행의 상태가 아님. 스펙/재고 상 "발급 가능"의 개념적 표현. 쿠폰번호는 구매 시점 생성이므로 발급현황에 이 상태 행 없음.
SOLD판매(발급)됨, 현장 사용 가능. 발급된 쿠폰의 초기 상태.
USED현장 사용 완료.
CANCELLED주문 취소로 무효화됨.

수량단위 부분취소 운영 (v0.14 전면 개정)
✅ v0.14 개정 — 부분취소 허용. 프로토타입(v0.8) 기반 정책 반영. 종전 "전체 취소만(v0.6)" 정책을 폐지하고 상품(권종)+수량 단위 부분취소를 도입한다. 미결 신규-3 해소.
부분취소 기본 규칙
· 취소 단위: 상품(권종) + 수량. 개별 쿠폰 번호 단위가 아닌 권종·수량을 선택해 일괄 취소.
· 취소 대상: SOLD(미사용) 상태의 쿠폰만 선택 가능. USED(사용 완료) 쿠폰은 취소 선택 불가.
· 환불 금액: 선택 취소한 쿠폰의 판매가 합계 전액 환불. 위약금 없음(전액 환불 원칙).
· 주문 상태 전환: 일부만 취소 → 부분취소 / 전체 취소 → 취소완료.
· USED 포함 주문: USED 쿠폰이 있어도 SOLD 쿠폰만 선택해 부분취소 진행 가능. USED 쿠폰은 현장 /cancel(사용취소) 처리 후에만 SOLD로 복원되어 취소 대상이 됨.
취소 주체경로처리 가능 내용
고객프런트 마이페이지 → 주문 상세오픈형: 사용기간 종료일 이전 SOLD 쿠폰 전체 취소. 날짜지정형: 취소 구간 내 전체 취소. (부분취소는 현재 프런트 미제공 — 관리자 처리)
관리자(CS)어드민 S15-B상품+수량 단위 선택 부분취소 또는 전체 취소. SOLD 쿠폰만 선택 가능.
오픈형 부분취소 기준: 사용기간 종료일(use_end_date) 이전이며 SOLD 상태인 쿠폰만 부분취소 가능. 종료일 이후 또는 USED 쿠폰은 환불 불가(8.2절 오픈형 취소 특례 동일 적용).
날짜지정형 부분취소 기준: 이용일 기준 취소 구간(8.2절) 내 SOLD 쿠폰에 한해 부분취소 가능. 위약금율은 개별 쿠폰 판매가 × 구간별 위약금율 적용.
