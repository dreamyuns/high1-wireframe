공통 전제 — 이 화면 전체에 적용
· 이 화면은 무엇인가요? 메인·브릿지의 공용 검색바에서 [검색]을 누르면(로딩 약 2초) 이동하는 검색결과 목록입니다(경로 #/search). 브릿지(REF-2)와 같은 함수(renderListing)로 그려지며, 브릿지는 "숙소 1곳 안"의 객실만, 검색결과는 모든 숙소를 통틀어 조건에 맞는 객실을 모아 보여 준다는 점이 다릅니다.
· 카드 1장 = 객실 1개입니다. 한 객실에 상품이 여러 개면, 그중 예약 가능하고 가장 싼 상품 1개만 골라 카드로 보여 줍니다(최저가 대표). 예약 가능한 상품이 하나도 없는 객실은 목록에서 빠집니다.
· localStorage 키(값을 저장해 두는 브라우저 저장소의 이름표): 숙소 high1_places_v1 · 객실 high1_rooms_v1 · 상품 high1_products_v1 · 시설 high1_facilities_v2 · 침대유형 high1_room_master_bed_type_v1 · 객실유형 high1_room_master_room_type_v1
· 데이터가 오는 두 곳(이원 구조): 재고·요금·판매마감은 객실(S04-INV / room.inventory)에서, 마진·예약조건(취소·컷오프 등)은 상품(S06-B / product.inventory)에서 각각 가져와 합쳐 계산합니다.
· 다국어: 외국인 전용 사이트로 국문(KO)은 쓰지 않습니다. 모든 이름 필드는 영어(EN, 필수) / 중국어(ZH, 선택) 두 벌로 저장하며, 중국어가 없으면 영어로 대체 표시합니다.
· ※ 프로토타입 후속 반영: 현재 프런트 프로토타입은 아직 옛 KO/EN 토글 방식이라, 이 문서는 목표형(EN/ZH)으로 표기하고 해당 부분에 안내를 답니다.

검색결과 페이지 주석 (callout ①~⑫)

1
공용 검색바 — 일정(듀얼 캘린더) + 인원·객실
메인·브릿지와 똑같이 쓰는 공용 검색바입니다. 결과 화면 위쪽에도 그대로 있어 조건을 바꿔 다시 검색할 수 있습니다.
· 일정: 두 달치 달력 2개가 함께 열려 체크인·체크아웃을 자유롭게 고릅니다(1박 고정 아님).
· 인원·객실: 객실을 추가/삭제하고 객실마다 성인·아동 수를 정합니다(1객실 최대 8명, 최대 5객실).
· [검색]을 누르면 로딩(약 2초) 후 결과를 다시 계산합니다.
재고·요금 = S04-INV(객실) / 마진·예약조건 = S06-B(상품)
재고·요금·마감: high1_rooms_v1[].inventory[YYYY-MM-DD].{price, avlb_cnt, closed}
예약조건·마진: high1_products_v1[].inventory[YYYY-MM-DD].{checkin_allowed, cutoff_days_before_checkin, margin_type, margin_value}
검색바(renderSearchBar) → 검색 시 commitSearch → 로딩 2초 → 결과 목록 재계산
각 상품 예약 가능 판단 순서(evaluateProductForStay): need_dates → 판매기간(sale_out) → 투숙가능기간(no_inv) → 체크인 허용(closed) → 컷오프(cutoff) → 재고(soldout · 잔여재고 AVLB_RM_CNT ≤ 0) → ok
재고 3값: AVLB_RM_CNT(잔여 · sold out 기준) / OPER_RM_CNT(총 운영) / RSV_CNT(예약된 수)
2
좌측 필터 — 정렬
결과를 낮은 가격순 / 높은 가격순으로 다시 줄 세웁니다. 기본값은 낮은 가격순입니다. 정렬 기준 가격은 각 카드의 회원가(박 합산 판매가)입니다.
화면 안에서만 정렬(별도 저장·API 호출 없음). 검색결과 화면 전용(브릿지에는 정렬·숙소 필터 없이 룸타입 필터만)
3
좌측 필터 — 숙소
결과에 나온 숙소들만 체크박스로 보여 줍니다(결과에 없는 숙소는 항목 자체가 안 나옴). "전체"를 켜면 모두 표시, 개별 숙소를 체크하면 그 숙소만 골라 봅니다(여러 개 동시 선택 가능).
어드민 S02-1 Step1 · 숙소명
high1_places_v1[].place_name_en/_zh (결과에 포함된 숙소만 자동 수집)
좌측 필터 "숙소" 체크박스 목록
4
좌측 필터 — 룸타입
결과에 나온 객실유형(룸타입)만 알약 버튼으로 보여 줍니다. "전체" 또는 개별 룸타입을 눌러 골라 봅니다(여러 개 동시 선택 가능).
어드민 S09 객실유형관리 · 객실유형 마스터
high1_rooms_v1[].room_type_id → high1_room_master_room_type_v1[].name
좌측 필터 "룸타입" 토글 버튼 (전체 / 개별 룸타입)
5
결과 헤더 — 제목 · 회원가 안내 · 총 건수 (+ 수용 필터)
"검색 결과" 제목, "로그인 회원은 회원 전용가로 예약할 수 있습니다" 안내, 그리고 필터까지 적용된 총 건수(총 N건)를 표시합니다.
어드민 S03 객실 등록 · 최대인원(max_occupancy)
high1_rooms_v1[].max_occupancy · high1_rooms_v1[].visibility · high1_places_v1[].visibility
결과 목록 위 헤더(제목/안내/총 건수)
수용 필터: 요청 인원(요청 객실 중 인원이 가장 많은 객실 = reqMax)이 객실 최대인원보다 크면 목록에서 제외 → 즉 reqMax ≤ max_occupancy 인 객실만 노출.
그리고 노출 조건: 객실 visibility ≠ HIDE, 소속 숙소 visibility ≠ HIDE, 예약 가능(ok) 상품이 1개 이상 있어야 목록에 나옵니다.
6
숙소명 뱃지
카드 맨 위에 이 객실이 속한 숙소명(place_name)을 작은 뱃지로 표시합니다. 검색결과는 여러 숙소가 섞여 나오므로, 어느 숙소인지 바로 알 수 있게 뱃지가 특히 중요합니다.
어드민 S02-1 Step1 · 숙소명
high1_places_v1[].place_name_en/_zh
카드 맨 위 뱃지 텍스트 = 숙소명
7
객실명 + 상품명
객실명(작게)과 상품명(크고 굵게)을 2줄로 표시합니다. 카드 1장은 한 객실을 나타내며, 상품명은 그 객실의 최저가 예약가능 상품 이름입니다.
어드민 S03 객실 등록 · 객실명 / S06 상품 등록 · 상품명
high1_rooms_v1[].room_name_en/_zh · high1_products_v1[].name_en/_zh
카드 1행(객실명 — 연한 색) / 2행(상품명 — 굵게)
상품유형은 ROOM_ONLY(객실만) 하나로 운영합니다. (PACKAGE 없음)
8
정보 라인 — 크기 · 침대 · 인원
📐 객실크기(㎡) · 🛏 침대("{침대유형} {개수}개" 나열) · 👥 인원(기준/최대)을 3줄로 표시합니다.
어드민 S03 객실 등록 · 객실크기 / 침대유형·개수 / 기준인원 / 최대인원
high1_rooms_v1[].room_size_sqm · high1_rooms_v1[].bed_rows[]{bed_type_id, count} → high1_room_master_bed_type_v1[].name_en/_zh · standard_occupancy · max_occupancy
카드 정보 3줄: "📐 N㎡" / "🛏 {유형} {N}개" / "👥 기준 N명 / 최대 N명"
9
객실 대표 시설 칩 (ROOM)
객실에 지정한 대표 시설을 칩으로 나열합니다. 숙소 전체 시설(PLACE 도메인)과 별개로, 객실별 시설(ROOM 도메인)에서 대표로 고른 항목입니다.
어드민 S03 객실 등록 · 시설 선택 (ROOM 도메인, 대표 설정)
high1_rooms_v1[].featured_facility_ids → high1_facilities_v2[].name_en/_zh (ROOM 도메인)
카드 시설 칩 행
10
취소정책 표시 (2가지 상태)
상품의 취소 정책에 따라 2가지로만 표시합니다.
어드민 S06-A 취소정책 → cancel_policy_type / cancel_free_days_before
high1_products_v1[].cancel_policy_type · high1_products_v1[].cancel_free_days_before
① FREE_N_DAYS(무료취소 N일 전): 오늘 < (체크인 − N)일 → "{체크인 − N − 1}일 23:59까지 무료취소 가능" (파란색 볼드)
② NON_REFUNDABLE(환불불가) 또는 무료취소 기간 지남 → "취소 및 환불불가" (빨간색 볼드)
cancelSummaryLine() 함수가 판단. 카드 가격 패널에 표시됩니다.
11
인원추가요금 안내 (조건부)
검색한 인원(요청 객실 중 최대 인원 = reqMax)이 객실 기준 인원보다 많을 때만 "인원추가요금이 발생할 수 있습니다"를 표시합니다. 기준 인원 이하이면 나오지 않습니다.
어드민 S03 객실 등록 · 기준인원(standard_occupancy)
조건: reqMax > high1_rooms_v1[].standard_occupancy (단, ⑤ 수용 필터를 통과해 reqMax ≤ max_occupancy 인 객실만 카드로 나옴)
카드 안내 문구 (조건 충족 시에만 노출)
실제 추가요금 정책·금액은 상품 카드가 아니라 상세/정책 레이어에서 안내합니다. (숙소 단위 · REF-3 소관)
12
판매가 — MEMBER RATE / 회원가
체크인~체크아웃 각 박의 판매가를 더한 합계입니다. 예약 가능(ok)일 때만 금액이 나오고, 그 외에는 상태 메시지(판매 기간 외·예약마감·컷오프 등)가 나옵니다. (검색결과 목록에는 애초에 예약 가능 상품만 올라오므로 대부분 금액이 표시됩니다.)
입금가(원가) = S04-INV(객실) · 마진 = S06-B(상품)
판매가 = high1_rooms_v1[].inventory[날짜].price(입금가) + 마진(high1_products_v1[].inventory[날짜].margin_type/value)
ok → "MEMBER RATE / 회원가 + ₩금액" / 그 외 → 상태 메시지
판매가 = 입금가 + 마진, 소수점 버림(floor). computeSellPriceFront() 함수. 고객에게는 입금가(원가)를 노출하지 않습니다.
REF-8 · 티켓 티켓 검색결과 페이지 데이터 매핑 — 어드민 입력 → localStorage → 프런트 노출 · 경로 #/ticket/search
티켓 공통 전제 — 티켓 검색결과 화면 전체에 적용 · 기준: 정책서 v0.12 §13
· 이 화면은 무엇인가요? 공용 검색바를 Ticket(티켓) 모드로 바꾼 뒤 [검색]을 누르면 이동하는 티켓 검색결과 목록입니다(경로 #/ticket/search). 숙소 검색결과와 똑같은 UI(좌측 필터 + 상품 카드)를 그대로 재사용합니다. 다른 점은 검색바가 "일정·인원"이 아니라 "사용일 하루"를 고른다는 것과, 카드가 객실이 아니라 티켓 상품이라는 점입니다.
· 카드 1장 = 티켓 상품 1개입니다(숙소는 카드 1장 = 객실 1개였습니다). 상품 안에 성인·아동 같은 여러 옵션(레벨)이 있으면, 카드에는 옵션별 가격을 모두 보여 주고 가장 싼 옵션 가격을 "최저가"로 대표 표시합니다.
· localStorage 키(값을 저장해 두는 브라우저 저장소의 이름표): 티켓 상품 high1_ticket_products_v1 · 쿠폰 스펙(옵션·가격) high1_coupon_specs_v1 · 카테고리 high1_ticket_categories_v1 · 티켓 마진 high1_ticket_margin_master_v1
· 노출 조건(4가지 모두 충족해야 카드가 나옵니다 · §13.1): ① 상품 노출 ON(visibility ≠ N) AND ② 연결된 쿠폰 스펙 토글 ON(active) AND ③ 오늘이 판매기간(sale_start_date ~ sale_end_date) 안 AND ④ 검색한 사용일이 사용기간(use_start_date ~ use_end_date) 안. 하나라도 어긋나면 목록에서 빠집니다.
· 콘텐츠가 오는 두 곳(소유 이원 구조 · §13 / 정책서 콘텐츠 소유 재정의): 썸네일(카드 이미지)은 상품(S14)이 가지고, 상세 소개·이용안내·취소환불 안내는 카테고리(S17)가 가집니다. 검색결과 카드는 썸네일만 사용하고, 상세·안내는 [상세보기] 모달에서 카테고리 것을 불러옵니다.
· 다국어: 외국인 전용 사이트로 국문(KO)은 쓰지 않습니다. 이름·안내는 영어(EN, 필수) / 중국어(ZH, 선택)로 저장하며, 중국어가 없으면 영어로 대체합니다.
· ※ 프로토타입 후속 반영: 현재 프런트 프로토타입은 아직 옛 KO/EN 토글 방식이라, 이 문서는 목표형(EN/ZH)으로 표기합니다. (기준: admin v0.7.11 / front v0.8.5)

티켓 검색결과 주석 (callout T1~T14)

T1
공용 검색바 — 티켓 모드(사용일 하루)
숙소와 똑같은 공용 검색바를 Ticket 모드로 바꾼 모습입니다. 숙소는 "일정(체크인·체크아웃)+인원"을 고르지만, 티켓은 사용일(티켓을 쓸 하루) 하나만 고릅니다.
· 사용일 기본값 = 오늘 +7일(§13.1). 처음 들어오면 자동으로 오늘로부터 7일 뒤 날짜가 들어가 있습니다.
· 고객이 날짜를 바꾸고 [검색]을 누르면 그날 기준으로 목록을 다시 계산합니다.
검색바(renderSearchBar, searchDomain="ticket") → 검색 시 로딩 → 결과(#/ticket/search, renderTicketSearch)에서 사용일 기준 재계산
사용일 기본값은 addCalendarDaysYmd(오늘, 7)로 계산합니다. (정책서 v0.12 §13.1)
T2
좌측 필터 — 정렬
결과를 낮은 가격순 / 높은 가격순으로 다시 줄 세웁니다. 기본값은 낮은 가격순입니다. 정렬 기준 가격은 각 카드의 최저가(가장 싼 옵션 판매가)입니다.
화면 안에서만 정렬(별도 저장·API 호출 없음). 숙소 검색결과와 동일한 좌측 필터 구조를 재사용합니다.
T3
좌측 필터 — 카테고리
숙소 검색결과의 "숙소·룸타입" 필터 자리에, 티켓은 카테고리(1뎁스) 체크박스가 들어갑니다. "전체"를 켜면 모두, 개별 카테고리를 체크하면 그 카테고리 티켓만 골라 봅니다(여러 개 동시 선택 가능).
어드민 S17 카테고리 관리 · 1뎁스 카테고리명
high1_ticket_categories_v1[].name_en/_zh (parent_id 없는 1뎁스만) · 상품 매칭 키 = high1_ticket_products_v1[].category_1
좌측 필터 "카테고리" 체크박스 목록 (tk-cat / tk-cat-all)
T4
결과 헤더 — 제목 · 사용일 안내 · 총 건수
"검색 결과" 제목과 함께 "사용일 {날짜} 기준 · 그날 사용 가능한 판매중 티켓" 안내, 그리고 필터까지 적용된 총 건수(총 N건)를 표시합니다.
결과 목록 위 헤더(제목/사용일 안내/총 건수)
노출 판정 순서: ticketVisibleNow(상품 노출 ON + 스펙 active + 오늘이 판매기간 안) → ticketUsableOn(사용일이 사용기간 안) → 카테고리 필터 → 정렬. 4가지를 모두 통과한 상품만 목록에 나옵니다. (§13.1)
T5
썸네일 (상품 소유 · S14)
카드 왼쪽 이미지입니다. 썸네일은 상품(S14)이 가진 이미지를 씁니다(카테고리 히어로 이미지가 아닙니다). 이미지가 여러 장이면 이전/다음 화살표로 넘길 수 있습니다.
어드민 S14 티켓 상품 등록 · 상품 이미지(썸네일)
high1_ticket_products_v1[].thumb_meta / hero_meta / image_meta (이미지 URL)
카드 썸네일(ticketGallery로 이미지 모음 → 이전/다음)
상세 소개·이용안내·취소환불 안내는 카테고리(S17) 소유라 카드에는 안 나오고 [상세보기] 모달에서 불러옵니다. 카드는 썸네일만 사용합니다. (정책서 v0.12 콘텐츠 소유 재정의)
T6
카테고리 뱃지
카드 맨 위에 이 티켓이 속한 카테고리를 작은 뱃지로 표시합니다. 2뎁스(상품유형)가 있으면 "1뎁스 › 2뎁스"(예: Ski › Lift) 형태로 함께 보여 줍니다. 외국인 전용이라 항상 영어(name_en)로 표기합니다.
어드민 S17 카테고리 관리 · 카테고리명(1뎁스/2뎁스)
high1_ticket_products_v1[].category_1 / category_2 → high1_ticket_categories_v1[].name_en
카드 맨 위 뱃지 텍스트 = 카테고리(ticketCatEnLabel)
T7
상품명
티켓 상품 이름을 크고 굵게 표시합니다. 카드 1장은 티켓 상품 1개를 나타냅니다.
어드민 S14 티켓 상품 등록 · 상품명(EN 필수/ZH 선택)
high1_ticket_products_v1[].name_en/_zh
카드 상품명(굵게)
T8
사용기간
🗓 이 티켓을 현장에서 쓸 수 있는 기간(시작일 ~ 종료일)입니다. 연결된 쿠폰 스펙에 저장된 값을 그대로 보여 줍니다.
어드민 S13 쿠폰 스펙 · 사용기간(use_start_date / use_end_date)
high1_coupon_specs_v1[].use_start_date · high1_coupon_specs_v1[].use_end_date (spec_coupon_id로 상품과 연결)
카드 정보 줄 "🗓 사용기간 {시작} ~ {종료}"
T9
예약 가능 인원 (성인·아동 / 성인 전용)
👥 이 티켓을 예약할 수 있는 대상을 표시합니다. 쿠폰 스펙의 레벨로 판단합니다: 레벨 1=성인, 레벨 2=아동.
· 성인·아동 옵션이 모두 있으면 "성인·아동 예약가능"
· 성인 옵션만 있는 티켓(예: 곤돌라 왕복권)은 "성인 예약가능(성인 전용)"으로 구분해 표시합니다.
어드민 S13 쿠폰 스펙 · 레벨(level / level_name)
high1_coupon_specs_v1[].level (1=성인 / 2=아동) · level_name
카드 정보 줄 "👥 …예약가능" (ticketPaxLabel)
T10
레벨별 판매가
👤 성인·아동 등 옵션(레벨)마다 판매가를 한 줄씩 보여 줍니다. 판매가는 입금가(원가) + 마진으로 계산하며, 고객에게 입금가는 노출하지 않습니다.
입금가 = S13 쿠폰 스펙 · 판매가(price) / 마진 = S11 티켓 마진(쿠폰ID 단위)
판매가 = high1_coupon_specs_v1[].price(입금가) + 마진(high1_ticket_margin_master_v1[쿠폰ID])
카드 옵션 줄 "👤 {레벨} ₩금액" (ticketLevelSell → computeSellPriceFront)
판매가 = 입금가 + 마진, 소수점 버림(floor). 마진 미설정 시 전역 디폴트 30,000원. (정책서 §11)
T11
티켓 방식 칩 — 오픈형
이 티켓이 오픈형(사용기간 안에서 아무 때나 자유이용)임을 칩으로 표시합니다. 현재는 오픈형 단품 위주로 운영합니다.
어드민 S14 티켓 상품 등록 · 판매 방식(오픈형/날짜지정형)
카드 칩 "오픈형 · 사용기간 내 자유이용"
날짜지정형은 선택한 날짜에 판매 한도 > 0이고 커트오프 미경과일 때만 노출됩니다. (정책서 v0.12 §13.2)
T12
상세보기 버튼
누르면 상세보기 모달이 열립니다. 모달 안의 상세 소개·이용안내·취소환불 안내는 카테고리(S17)가 가진 내용을 불러옵니다.
어드민 S17 카테고리 관리 · 상세설명·이용안내·정책 (카테고리 소유)
high1_ticket_categories_v1[].detail_html_en / guide_html_en 등
[상세보기] → openTicketModal(상품ID)
T13
취소 안내 — 사용종료일 이전 무료취소
오픈형 티켓은 이용일(사용할 특정 날짜)이 없으므로 숙소식 "N일 전 무료취소" 대신 "사용종료일 이전 무료취소"로 안내합니다.
카드 가격 패널의 취소 안내 문구(파란색 볼드)
오픈형 취소 기준: 사용기간 종료일(use_end_date) 전 미사용(SOLD)=전액 환불 / 종료 후=환불 불가 / 사용완료(USED)=환불 불가. (정책서 v0.12 §8.2 오픈형 취소 특례)
T14
최저가 — FROM / 최저가
카드에 담긴 옵션(레벨) 판매가 중 가장 싼 값을 대표 가격으로 보여 줍니다(예: 성인·아동 중 더 싼 아동가). "최저가"임을 함께 표기해 옵션에 따라 가격이 달라질 수 있음을 알립니다.
입금가 = S13 쿠폰 스펙 · 판매가(price) / 마진 = S11 티켓 마진
최저가 = min( 각 레벨 판매가 ) = min( high1_coupon_specs_v1[].price + 마진 )
카드 가격 패널 "FROM / 최저가 + ₩금액" (ticketMinPrice)
