1전체 연동 아키텍처
API 방향 구분
구분호출 방향우리 역할
숙소 PMS (객실/요금/예약)우리 → High1 호출API 클라이언트

티켓 쿠폰 조회·사용·취소는 우리(OTA)가 요청하는 것이 아니라, 하이원이 우리 API URL을 호출하는 구조. 우리는 서버를 구현하고 하이원이 그 URL을 호출한다.
전체 플로우
[하이원 마케팅팀] 쿠폰 스펙 전달(엑셀) — 쿠폰ID·레벨별 입금가·적용상품·사용기간 ▼ [우리 어드민] 스펙 등록(S13 CSV) → 상품 생성(S14-B 기본·마진·취소정책 / S14-C 날짜·한도·커트오프) ※ 쿠폰번호 생성은 "구매 시점"(12자리 규칙) — 스펙/상품 단계에선 미발급 ▼ [고객 구매 완료] 쿠폰번호 발급(이메일/마이페이지) → DB 상태: SOLD (발급 시점 생성) 주문 생성(S15) · 쿠폰 발급이력(S16) ▼ [고객 현장] 쿠폰 제시 → High1 POS/KIOSK: GET /search → 우리 서버 DBOK/DBER ▼ High1 POS/KIOSK: GET /use → 우리 서버 SOLD→USED, DBOK → 고객 시설 이용 ▼ [사용취소·현장 실수 복원] High1 POS/KIOSK: GET /cancel → 우리 서버 USED→SOLD 복원, DBOK
2쿠폰번호 구조 및 생성 규칙
쿠폰번호 형식 (12자리)
쿠폰ID(3) + 레벨(1) + 쿠폰 일련번호(6) + 유효번호 난수(2) 예시: AML 1 000001 57 → AML100000157
구성자리수설명
쿠폰 ID3High1이 대행사별 부여하는 식별자(스펙 파일 시트명). 예: DBO, DBR, DC1
레벨1상품 구분 (LV.1=대인, LV.2=소인 등)
쿠폰 일련번호6000001~999999, 우리가 순차 발급
유효번호(난수)2일련번호 패턴 노출 방지용 난수
BARCODE 12자리 확정 (v0.5, M-13 해소): High1 개발팀 Q&A 답변에서 "앞 3자리 쿠폰ID + 1자리 레벨 + 6자리 일련번호 + 2자리 유효번호(난수)"로 확인. 소셜연동 규격서(2018)의 "10자리" 기재는 오기. 12자리가 실제 운용 스펙.
CVX 형식 주의: 참고 엑셀의 CVX-1-XXXXXXXX는 기존 다른 대행사/이전 시스템 형식. 우리는 미사용, 위 12자리 규칙을 따른다.
생성 주체 및 시점
단품: 고객 결제 완료 시 우리 시스템이 12자리 쿠폰번호 자동 생성. High1 사전 등록/통보 불필요, 즉시 고객 전달.
쿠폰번호는 구매(결제 완료) 시점에 생성된다. 스펙 등록·상품 생성 단계에서는 쿠폰번호가 발급되지 않는다. 따라서 발급현황(S16)에는 판매 전(AVAILABLE) 상태의 쿠폰 행이 존재하지 않는다. (5절 참고)
패키지(객실+티켓): 패키지 전용 쿠폰은 일반 쿠폰과 별도 입금가가 존재(패키지 전용 < 일반). 흐름: ① PMS 객실 예약 완료(API 6) → ② 하이원 예약번호(rsv_id) 수령 → ③ 쿠폰번호 12자리 생성 → ④ High1 신규 API에 예약번호↔쿠폰번호 매핑 등록.
패키지 취소 시: OTA는 룸만 PMS 취소(API 7). 패키지 쿠폰 취소/변경은 OTA가 High1에 API 통보 필요(Q7 답변). 단품 취소는 High1 통보 불필요. 패키지 매핑·취소 통보 API 모두 현재 High1 미개발(M-03) — 단품 연동 완료 후 별도 협의.
레벨 구조 / 유니크 규칙
LV.1=대인 / LV.2=소인 / LV.3~8 미사용 예약. 현장에서 성인·소인 별도 확인 없이 레벨별 상품 목록만 표시(Q23 답변). 쿠폰 레벨 = 상품 구분자 역할만 함.
동일 쿠폰ID+레벨 내 유니크. CANCELED 번호는 재사용 가능, USED 번호는 재사용 불가(Q14 답변).
레벨 구성은 카테고리(스키/워터파크)에 따라 상이. 스펙 파일 수령 후 확정.
3쿠폰 스펙 파일 구조
스펙 파일 개요
High1 마케팅팀이 대행사에 제공하는 엑셀. 시트 1개 = 쿠폰 코드(ID) 1개(시트명 = 쿠폰 코드, 예: DBO/DBR/DBT), 한 파일에 대행사/판매유형별 여러 시트 존재. 워터월드 성수기 샘플 기준 구조 파악.
주요 필드 (노란색 음영 컬럼 기준)
필드내용비고
쿠폰코드시트명과 동일. 쿠폰번호 앞 3자리(쿠폰ID)예: DBO, DBR, DC1
이용권명스펙 헤더 상단의 상품 식별명 (예: OAT_26성수기_얼리_워터월드)내부 식별용, 시트 상단 1개 기재
레벨(LV.1, LV.2…)행별 레벨 구분
쿠폰명레벨별 노출 이름 (예: 워터월드 종일권_성수기(대인/얼리))고객 표시명
적용금액(입금가)High1에 납부하는 원가고객 미노출
할인대상 내역적용 가능 PMS 상품 목록 (예: 종일권_대인_남_4계절 상품 외 15종)
사용기간 (use_start/use_end)고객 현장 사용 가능 기간. 2컬럼 관리, 판매기간 미관리
여신IDHigh1 내부 정산 계정 식별자 (대행사별 상이)참고용
인쇄기간 미사용 확정: 인쇄기간(판매 시작 가능 기간) 미관리. 사용기간(2컬럼)만 관리.
사용인원 미사용: 원본 엑셀에 사용인원(1인 1쿠폰 기준) 컬럼이 있으나 우리 CSV 템플릿에서는 제외. 1인 1쿠폰 원칙은 7절 재고 관리로 적용.
워터월드 2026 성수기 입금가 / 판매유형
LV.1 대인 40,000원 / LV.2 소인 35,000원.
판매유형 3종(얼리·상시·프로모션, 사용기간 2026-07-10~08-30) — 유형별 쿠폰 코드 상이 → 어드민에서 유형별 별도 스펙 등록.
채널사(플레이스토리/티브리지/스마트인피니/코어웍스)별로 쿠폰 코드 상이 → 우리(AllmyTour)도 자체 쿠폰 코드를 High1로부터 받아야 함.
액션: High1 해외마케팅 담당자에게 우리 전용 쿠폰 코드 발급 요청 (미결 M-04).
4API 명세 (우리가 구현할 서버)
개요
API 3개(영업장·상품 구분 없이 통합) · HTTP GET · 인증 없음(Q16 답변) · HTTPS 미확인(M-01, Q17 공란). 기존 규격서의 lift_*/hiww_ent_* 구분 불필요(Q15 답변). 영업장별 별도 endpoint 없음.
약식 URL: 조회 /search?barcode= · 사용 /use?barcode= · 취소 /cancel?barcode=. URL 등록: 우리 서버 URL을 High1 개발팀 담당자에게 전달 → POS/KIOSK 설정값으로 반영(10절).
응답코드 기준 (소셜연동 규격서 2018)
응답 코드(RESULT/MSG)는 소셜연동 규격서(2018) 기준. 규격서 실제 엔드포인트는 hiww_ent_search.jsp / hiww_ent_use.jsp / hiww_ent_usecancel.jsp, 파라미터 BARCODE(대문자), 응답 = BARCODE + RESULT + MSG. 위 /search·/use·/cancel는 설명용 약식 표기.
(1) 조회 — GET /search (hiww_ent_search.jsp?BARCODE=)
RESULTMSG의미우리 처리
DBOKUSE ABLE유효·사용 가능SOLD 확인 후 반환
DBER01BARCODE LENGTH ERR자릿수 오류(12자리 아님)형식 오류
DBER02NO SEARCH BARCODE쿠폰번호 미존재DB에 없는 번호
DBER03USED BARCODE이미 사용됨USED 상태
DBER04CANCELED BARCODE취소됨CANCELED 상태
DBER31/32BEFORE STARTDATE / AFTER ENDDATE유효기간 이전/경과미발생 처리 (날짜 체크 제거)
(2) 사용 — GET /use / (3) 사용취소 — GET /cancel
/use(hiww_ent_use.jsp): SOLD→USED (DBOK/USE OK). 미존재 DBER02·이미 사용 DBER03·취소된 쿠폰 DBER04 오류.
/cancel(hiww_ent_usecancel.jsp): USED→SOLD 복원 (DBOK/USECANCEL OK). 고객이 하이원 결제 후 취소 요청 시 재사용 가능 상태 복원 목적으로 하이원이 호출. 고객 구매 취소(OTA 환불)와 무관(Q7). 시간 제한 없음(Q8). 단품은 High1 별도 통보 불필요, 패키지 쿠폰 취소는 High1 API 통보 필요(2.2절·8절).
날짜 유효성 정책 / API 순서
날짜 유효성 체크 미구현 — DBER31/32 미발생, 날짜 범위는 어드민 표시용. 각 API 독립 동작(조회 없이 사용 단독 호출도 유효, Q5).
배경: 운영 중 유효기간 초과 후에도 현장 사용 필요 케이스 반복 발생 → High1 요청 (Q4).
5쿠폰 상태 관리
쿠폰번호는 구매(결제 완료) 시점에 생성된다(2.2절). 실제 발급된 쿠폰 행은 처음부터 SOLD 상태로 생성되며, 발급현황(S16)에는 판매 전(AVAILABLE) 상태의 쿠폰 행이 존재하지 않는다. AVAILABLE은 "발급 가능한 스펙/재고 개념"일 뿐, 발급된 쿠폰 행의 상태가 아니다.
[구매(결제 완료) 시점에 쿠폰번호 생성] ▼ SOLD ──── 주문 취소(자동/수동) ──→ CANCELED ← 발급 즉시 초기 상태 │ High1 /use ▼ USED ──── High1 /cancel(사용취소·현장 실수 복원) ──→ SOLD(복원)
상태의미
(AVAILABLE)발급된 쿠폰 행의 상태가 아님. 스펙/재고 상 "발급 가능"의 개념적 표현. 쿠폰번호는 구매 시점 생성이므로 발급현황에 이 상태 행 없음.
SOLD판매(발급)됨, 현장 사용 가능. 발급된 쿠폰의 초기 상태.
USED현장 사용 완료.
CANCELED주문 취소로 무효화됨.
6고객 데이터 관리
쿠폰별 고객 정보: 바코드(쿠폰)번호 · 사용가능일자(시작/종료, 표시용) · 상태(SOLD/USED/CANCELED) · 구입한사람이름 · 전화번호 · 이메일 · 국적 · 구매날짜 · 쿠폰명 · 권종(리프트권/렌탈/워터월드 등).
여권번호 수집 제외 확정(v0.2): 민감 개인정보(여권번호) 미수집. 외국인 식별은 국적만 수집(개인정보 최소화).
7재고 관리
재고 = 우리가 발급한 쿠폰 수. High1 별도 재고 관리 없음. 쿠폰 소진 개념 없음(Q13). 발급 한도는 우리 어드민에서 내부 제어. 추가 발급 시 High1 요청 불필요(일련번호 이어서 발급).
쿠폰 1개 = 1영업장 구조(Q10): 쿠폰 1개로 여러 영업장 동시 사용 불가. 스키 리프트권 + 장비렌탈을 함께 구매하면 각 권종마다 별도 쿠폰번호 발급. 복합 구매 시 바코드 개수 = 구매 수량의 합(1개씩 순차 스캔, Q22).

티켓 취소 정책 설정 (S14-B)
어드민 S14-B에서 상품별 직접 입력(수동). 숙소 취소정책(S06-A)과 동일 구조, 단 기준이 이용일(사용일)(숙소는 체크인 기준).
구간: 기준일 셀렉트(3일 이상 전 / 2일 전 / 1일 전 / 당일 24시 이전) + 위약금율(%). 1구간 이상 없으면 저장 불가.
위약금율 표기: 0% = 무료취소(전액환불) / 1~99% = 부분 위약금 / 100% = 환불불가. 1구간 이상 필수, 노쇼 고정행 없음(PO 결정).
구간1: 이용일 3일 이상 전 → 위약금율 0% (무료취소) 구간2: 이용일 2일 전 → 위약금율 50% 구간3: 이용일 당일 24시 이전 → 위약금율 100% (환불불가)

11마진 관리 정책
티켓 마진 = 쿠폰ID(coupon_id) 단위
v0.6 변경 — 티켓 마진 = 쿠폰ID 단위 재정의. 종전 "카테고리(1뎁스) 마스터 + S14-B 레벨별 개별 설정" 구조 폐기. coupon_id=관리 축 / category=필터 / level=옵션 재편에 맞춰, 마진은 쿠폰ID 단위로 설정. 한 쿠폰ID의 모든 레벨(대인·소인)은 동일 마진 적용. S11 마진관리에서 숙소/티켓 탭 통합 운영.
① S11 티켓 탭 — 쿠폰ID별 마진 설정 카테고리 선택(필터) → 해당 카테고리 쿠폰ID 목록 → 쿠폰ID별 마진(모든 레벨 동일) 미설정 쿠폰ID → 전역 디폴트 마진 적용 ▼ ② S14-B — 마진 읽기전용 표시 (연결 쿠폰ID 마진 표시만, 레벨별 개별 UI 없음)
설정 축 정리
관리 축 = 쿠폰ID. 마진은 S11 티켓 탭에서 쿠폰ID 단위로 설정.
category는 필터. S11에서 카테고리를 골라 그 안 쿠폰ID 목록을 좁히는 용도.
level은 옵션(구분자). 레벨별로 마진 차등 불가. 쿠폰ID 하나의 마진 = 그 안 모든 레벨 공통.
S14-B는 읽기전용. 상품 화면에서는 연결 쿠폰ID의 마진을 표시만 함.
마진 규칙
마진율(%) 또는 마진금액(정액) 선택. 마진율 -49%~+100%(정수만), 계산 결과 소수점 버림(floor). 음수=할인 / 양수=마크업. 이력 관리 필수(변경일시·변경자·전/후).
오픈형 상품의 마진
v0.4 주 운영 방식은 오픈형(날짜지정형 기능 유지). 오픈형은 날짜 지정이 없으므로 마진은 쿠폰ID 단위(S11 티켓 탭) 고정 설정 — 날짜별·레벨별 차등 없음. 판매가 = 입금가(스펙 적용금액) + 쿠폰ID 마진.
