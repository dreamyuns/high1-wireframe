화면 주석

1
편집 중인 상품 컨텍스트
탭1(S06-A)에서 선택된 숙소·객실·상품명을 상단에 표시. S06-A ↔ S06-B 간 이동 시 상품 정보 유지.
2
탭2 — 재고·요금 (인벤토리)
탭2는 목록형(S06-B)과 달력형(S06-C)으로 분리. 탭1(S06-A) 상품 마스터 저장 완료 후 탭2에서 인벤토리 입력.
3
목록형 뷰
날짜 행별로 입금가·판매가·재고·상태를 테이블 형식으로 표시. 개별 행 인라인 편집, 날짜 추가/삭제 가능.
달력형(S06-C)과 동일한 inventory[] 배열을 편집. 두 뷰는 동일 데이터 소스.
4
구간 일괄 적용
시작일~종료일 + 입금가·재고·체크인허용·최소박·최대박·컷오프를 한 번에 입력 후 '일괄 적용' 클릭. 기존 행은 덮어씀, 없는 날짜는 신규 생성. 판매가는 마진 적용으로 자동 계산.
일괄 적용 후 날짜별 세부 수정은 인라인 편집 또는 S06-C 달력형 사용.
5
기간 필터
인벤토리 행이 많을 때 특정 기간만 조회. 필터 적용 시 해당 범위 행만 표시됨.
6
입금가 (price)
해당 날짜의 1박 원가 (KRW). PMS연동 상품은 [요금 동기화] 버튼 실행 시 API 3(SELL_ITM_AMT) 동기화 금액, 수기 상품은 관리자 직접 입력. 마진 미적용 금액. (API 4 SELL_ITM_AMT 무시 확정)
→ 프런트: 미노출 (고객에게는 판매가만 표시)
20
판매가 (sell price) — 읽기 전용
입금가에 마진(S11 시설 마스터 또는 S06-A 상품 개별)을 적용한 고객 청구 금액. 자동 계산, 직접 수정 불가. 마진 변경 시 실시간 반영.
계산식: 입금가 × (1 + 마진율) 또는 입금가 + 마진금액. 소수점 버림(floor). 다박 예약 시 숙박 일수만큼 각 날짜 판매가 합산.
→ 프런트: 상품 카드 총 금액 (multi-night sum, 판매가 기준). API 6 SELL_AMT는 입금가로 전송 (판매가 아님).
7
사용가능 객실수 (읽기전용)
해당 날짜 남은 판매 가능 수량. 이 화면에서 수정 불가.
PMS연동 상품: API 4 RSV_CNT 값. 수기 상품: 총 재고 − 예약 수.
재고 변경은 객실 상세 > 재고관리 탭에서 수행. 0이면 SOLD OUT 표시.
→ 프런트: stock ≤ 0 → 상품 카드 'SOLD OUT' 상태
8
최소박 / 최대박 (min_stay_nights / max_stay_nights)
체크인일 기준 적용. 선택한 박수가 [min, max] 범위 밖이면 예약 불가.
→ 프런트: 박수 범위 벗어나면 상품 카드 '최소/최대 박수 제한' 상태
9
컷오프 (cutoff_days_before_checkin)
체크인 N일 전 자정부터 예약 차단. N=0이면 컷오프 없음 (당일 예약 가능).
→ 프런트: today ≥ (체크인 − N일) 이면 '예약 마감' 상태
10
상태 배지
각 날짜 행의 현재 상태를 시각화. 정상(초록) / SOLD OUT(빨강, stock=0) / 체크인불가(회색, check_in_allowed=N).
11
저장 시 날짜 중복 검증
inventory[] 내 동일 date 중복 여부를 자동 검증. 중복 발견 시 저장 차단 후 중복 날짜 목록 표시.
PR-FORM-04: 저장 시 날짜 중복 검증 필수.
12
체크인허용 (checkin_allowed)
Y: 해당 날짜에 체크인 가능. N: 재고가 있어도 신규 체크인 불가 (운영 정책으로 특정일 체크인 차단 시 사용).
→ 프런트: 상품 카드는 그대로 노출됨. 단, 해당 날짜를 체크인일로 선택하면 "예약 불가 (체크인 불가)" 표시. visibility(상품 노출 여부)와 무관.
연박 투숙 중 통과(stay-through)는 영향 없음. 체크인 날짜 당일에만 적용.
13
[+ 날짜 추가] 버튼
클릭 시 테이블 최상단에 신규 빈 행을 인라인 편집 모드로 삽입.
날짜 필드: 빈 date picker (필수 입력). 나머지 기본값 — 입금가: 빈값, 재고: 0, 체크인허용: Y, 최소박: 1, 최대박: 30, 컷오프: 1. 판매가: 입금가 입력 후 자동 계산.
날짜 미입력 상태로 [저장] 클릭 시 오류 표시 후 저장 차단.
14
[편집] 버튼
해당 행을 인라인 편집 모드로 전환. 모든 필드(입금가·재고·체크인허용·최소박·최대박·컷오프)가 input/select로 교체되고, 버튼 영역이 [저장]+[취소]로 바뀜. 판매가 셀은 읽기 전용으로 유지.
동시에 1행만 편집 가능. 다른 행 편집 중 [편집] 클릭 시 "저장되지 않은 변경사항이 있습니다" 경고.
15
행 [저장] / 행 [취소] 버튼
[저장]: 해당 행 변경사항을 페이지 state(메모리)에 반영. localStorage에는 아직 기록하지 않음. 편집 모드 종료 후 상태 배지 즉시 갱신.
[취소]: 변경 파기, 편집 전 원래 값으로 복원하고 편집 모드 종료.
행 [저장] ≠ localStorage 저장. 최종 기록은 하단 ⑰ [저장] 버튼에서 수행.
16
[삭제] 버튼
확인 다이얼로그 없이 해당 행을 페이지 state에서 즉시 제거. localStorage에는 아직 반영되지 않으므로, 하단 ⑱ [취소]로 페이지 전체를 되돌려 복구 가능.
하단 ⑰ [저장] 클릭 전까지는 실수로 삭제해도 ⑱ [취소]로 복구 가능.
17
하단 [저장] 버튼
탭1(S06-A) 마스터 정보 + 탭2(S06-B) 인벤토리 전체를 localStorage에 최종 기록. 실행 전 날짜 중복 자동 검증 (⑪) → 중복 있으면 저장 차단.
행 단위 [저장](⑮)과 다름. 이 버튼을 눌러야 실제 데이터가 저장됨.
18
하단 [취소] 버튼
페이지에서 작업한 모든 변경사항(행 추가·편집·삭제)을 파기하고 상품 목록(S05)으로 이동.
localStorage에 저장되지 않은 변경만 파기됨. 이미 저장된 데이터는 유지.
19
요금 동기화 (PMS연동 모드 전용)
[PMS연동 모드]: [요금 동기화] 버튼 클릭 시 API 3(otaHbItmInfo.do) 호출하여 날짜별 입금가(SELL_ITM_AMT) 갱신. 진입 시 자동 호출 없음. 요금 컬럼은 읽기 전용(편집·삭제 버튼 없음).
[수기 모드]: 이 배너 숨김. 기존 편집 UI(⑬~⑰) 그대로 표시.
재고 관리는 S04-INV에서 별도 수행(최초 1회 수동 동기화 필수 → 이후 배치 자동 업데이트). API 4 SELL_ITM_AMT 무시 확정 (하이원 2026-05-27).
[요금 동기화] 버튼 클릭 시: "PMS 요금 값으로 입금가가 덮어쓰기 됩니다. 진행하시겠습니까?" 확인 팝업 표시. 취소 시 동기화 중단.
PMS연동 모드에서는 입금가 직접 편집 버튼 비활성화.
21
이력 보기 (B안 — 날짜 필터 모달)
필터 바 오른쪽 [이력 보기] 버튼 클릭 시 변경이력 조회 모달 표시.
조회기간(시작일~종료일) 설정 후 [조회] 클릭 → 해당 기간 내 날짜별 인벤토리 변경 이력만 필터링 표시.
이력 기록 조건: 날짜별 입금가·재고 변경 시 자동 기록 (수동 저장 시점 기준).
이력 컬럼: 변경일시 / 변경자 / 적용날짜 / 변경구분(수동·PMS동기화) / 항목 / 변경 전 / 변경 후.
수동 변경과 PMS동기화는 배지로 구분. PMS동기화 이력은 별도 동기화 로그 테이블에서 조회.
