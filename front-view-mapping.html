· ※ 프로토타입 후속 반영: 현재 프런트 프로토타입 일부 경로는 아직 옛 KO/EN 토글 방식이라, 이 문서는 목표형(EN/ZH)으로 표기하고 해당 부분에 안내를 답니다.

1
숙소 선택 탭
위쪽 메뉴에서 고른 종류(HOTEL=호텔 / CONDO=콘도)에 해당하는 숙소들을 탭으로 늘어놓습니다. 탭을 누르면 그 숙소 화면으로 바뀝니다.
어드민 S02-1 Step1 · 숙소명 / 1차 분류
high1_places_v1[].place_name_en · place_name_zh · category
탭 글자 = 숙소명(EN, 없으면 대체), HOTEL/CONDO로 걸러 표시
2
Hero 이미지 슬라이더
숙소 이미지들을 큰 배경으로 넘겨 보여줍니다. ← → 버튼으로 넘기며, 이미지가 없으면 회색 자리표시가 나옵니다.
어드민 S02-3 Step3 · 이미지 등록
high1_places_v1[].image_meta[].data_url

Hero Overlay — 숙소명 · 2차 분류명
Hero 이미지 위 어두운 덮개에 숙소명(위)과 2차 분류명(아래)을 표시. "숙소 안내 보기" 버튼을 누르면 오른쪽에서 안내 레이어가 열립니다.
어드민 S02-1 Step1 · 숙소명 / 2차(건물·단지)
high1_places_v1[].place_name_en/_zh · high1_places_v1[].sub_place

Sticky Nav 탭 동작

Overview — 대표 시설 칩 (PLACE)
Overview 오른쪽에 대표 시설을 알약 모양 칩으로 늘어놓습니다. ★ 대표로 지정한 시설만 나옵니다.
어드민 S02-5 Step5 · ★ 대표 시설 선택 (PLACE 도메인 = 숙소 전체 시설)
high1_places_v1[].featured_facility_ids → high1_facilities_v2[].name_en/_zh
Overview 대표시설 칩 나열
7
검색바 — 일정(듀얼 캘린더) + 인원·객실
메인·검색결과·브릿지에서 똑같이 쓰는 공용 검색바입니다.
· 일정: 두 달치 달력 2개가 함께 열려 체크인·체크아웃을 자유롭게 고릅니다 (1박 고정 아님).
· 인원·객실: 객실을 추가/삭제하고 객실마다 성인·아동 수를 정합니다.
· 팝오버 바깥을 누르면 닫히고, 검색을 누르면 결과를 계산합니다.
재고·요금 = S04-INV(객실) / 마진·예약조건 = S06-B(상품)
재고·요금·마감: high1_rooms_v1[].inventory[YYYY-MM-DD].{price, avlb_cnt, closed}
예약조건·마진: high1_products_v1[].inventory[YYYY-MM-DD].{checkin_allowed, cutoff_days_before_checkin, margin_type, margin_value}
날짜 미선택 → 안내 문구 / 선택 후 → 각 카드에 요금 또는 상태 메시지
evaluateProductForStay 판단 순서: need_dates → sale_out → no_inv → closed(판매 OFF · CLSE_YN) → cutoff → soldout(잔여재고 AVLB_RM_CNT ≤ 0) → ok
재고 3값: AVLB_RM_CNT(잔여 · sold out 기준) / OPER_RM_CNT(총 운영) / RSV_CNT(예약된 수)
8
숙소명 뱃지
상품 카드 맨 위에 이 상품이 속한 숙소명(place_name)을 작은 뱃지로 표시합니다. (2차 분류명이 아니라 숙소명입니다.)
어드민 S02-1 Step1 · 숙소명
high1_places_v1[].place_name_en/_zh
카드 맨 위 뱃지 텍스트 = 숙소명
9
객실명 + 상품명
객실명(작게)과 상품명(크고 굵게)을 2줄로 표시. 같은 객실에 상품이 여러 개면 상품마다 카드가 따로 나옵니다.
어드민 S03 객실 등록 · 객실명 / S06 상품 등록 · 상품명
high1_rooms_v1[].room_name_en/_zh · high1_products_v1[].name_en/_zh
카드 1행(객실명 — 연한 색) / 2행(상품명 — 굵게)
상품유형은 ROOM_ONLY(객실만) 하나로 운영합니다. (PACKAGE 없음)
10
정보 라인 — 크기 · 침대 · 인원
📐 객실크기(㎡) · 🛏 침대("{침대유형} {개수}개" 나열) · 👥 인원(기준/최대)을 표시합니다.
어드민 S03 객실 등록 · 객실크기 / 침대유형·개수 / 기준인원 / 최대인원
high1_rooms_v1[].room_size_sqm · high1_rooms_v1[].bed_rows[]{bed_type_id, count} → high1_room_master_bed_type_v1[].name_en/_zh · standard_occupancy · max_occupancy
카드 정보 행: "📐 N㎡ · 🛏 {유형} {N}개 · 👥 기준 N명 / 최대 N명"
11
객실 대표 시설 칩 (ROOM)
객실에 지정한 대표 시설을 칩으로 나열. 숙소 전체 시설(PLACE 도메인)과 별개로, 객실별 시설(ROOM 도메인)에서 대표로 고른 항목입니다.
어드민 S03 객실 등록 · 시설 선택 (ROOM 도메인, 대표 설정)
high1_rooms_v1[].featured_facility_ids → high1_facilities_v2[].name_en/_zh (ROOM 도메인)
카드 시설 칩 행
12
취소정책 표시 (2가지 상태)
상품의 취소 정책에 따라 2가지로만 표시합니다.
어드민 S06-A 취소정책 → cancel_policy_type / cancel_free_days_before
high1_products_v1[].cancel_policy_type · high1_products_v1[].cancel_free_days_before
① FREE_N_DAYS(무료취소 N일 전): today < (체크인 − N)일 → "{체크인 − N − 1}일 23:59까지 무료취소 가능" (금색/파란 텍스트)
② NON_REFUNDABLE(환불불가) 또는 무료취소 기간 지남 → "취소 및 환불불가" (빨간 텍스트)
cancelSummaryLine() 함수가 판단. 날짜 미선택 시 미표시. 카드에서는 가격 패널에 표시됩니다.
13
판매가 — MEMBER RATE / 회원가
체크인~체크아웃 각 박의 판매가를 더한 합계입니다. 예약 가능(ok)일 때만 금액이 나오고, 그 외에는 상태 메시지가 나옵니다.
입금가(원가) = S04-INV(객실) · 마진 = S06-B(상품)
판매가 = high1_rooms_v1[].inventory[날짜].price(입금가) + 마진(high1_products_v1[].inventory[날짜].margin_type/value)
ok → "MEMBER RATE / 회원가 + ₩금액" / 그 외 → 상태 메시지(판매 기간 외·예약마감 등)
판매가 = 입금가 + 마진, 소수점 버림(floor). computeSellPriceFront() 함수. 고객에게는 입금가(원가)를 노출하지 않습니다.
14
인원추가요금 안내 (조건부)
검색한 인원이 객실 기준 인원보다 많을 때만 "인원추가요금이 발생할 수 있습니다"를 표시합니다. 기준 인원 이하이면 나오지 않습니다.
어드민 S03 객실 등록 · 기준인원(standard_occupancy)
조건: 검색 객실 중 최대 인원(reqMax) > high1_rooms_v1[].standard_occupancy
카드 안내 문구 (조건 충족 시에만 노출)
실제 추가요금 정책·금액은 상품 카드가 아니라 상세/정책 레이어에서 안내합니다. (숙소 단위 extra_fee_notes · REF-3 소관)
15
좌측 룸타입 필터 (간소화)
Rooms 목록 왼쪽에 룸타입 필터가 있습니다. 카테고리 맥락은 유지하지 않고 룸타입 정도로만 간소화했습니다. (검색결과 화면에는 정렬·숙소 필터도 함께 있음)
어드민 S09 객실유형관리 · 객실유형 마스터
high1_rooms_v1[].room_type_id → high1_room_master_room_type_v1[].name

REF-2 티켓 브릿지 페이지 데이터 매핑 — 카테고리 콘텐츠(S17) + 상품 선택(담기·장바구니) · 기준: 정책서 v0.12 §12.6 · front-prototype · 2026-07-10
1뎁스 카테고리 — 브릿지 화면 단위
위쪽 메뉴 "Ticket"에서 고른 1차 분류(스키·워터파크·식사권 등)의 브릿지 화면입니다. S17에서 관리자가 직접 등록한 카테고리입니다.
high1_ticket_categories_v1[].parent_id = null
2뎁스 상품유형 — 다크 서브탭(선택)
1뎁스 아래에 상품유형(리프트권·장비렌탈 등)이 있으면 상단에 어두운 서브탭으로 나옵니다. 2뎁스가 없으면 서브탭은 아예 표시되지 않습니다.
high1_ticket_categories_v1[].parent_id = (1뎁스 id)
공통 전제 — 이 티켓 브릿지 화면 전체에 적용
· 화면 뼈대 = 숙소 브릿지 컴포넌트 그대로 재사용: 상단 2뎁스 다크바(place-selector) · 큰 히어로(hero-fullwidth) · 따라 붙는 sticky 네비게이션(place-nav: 개요/상품선택/상세설명/안내/정책/위치) · 개요(Overview)를 숙소 브릿지와 같은 컴포넌트로 만듭니다. 히어로 글자는 상단 로고와 같은 왼쪽 선에 맞춰 좌측 정렬합니다.
· 브릿지 콘텐츠 주인 = 카테고리(S17): 히어로 이미지·개요·상세설명·이용안내·정책·위치는 상품이 아니라 카테고리(뎁스)가 소유합니다. 2뎁스 서브탭을 고르면 그 2뎁스 콘텐츠, 2뎁스가 없으면 1뎁스 콘텐츠를 씁니다. (정책서 v0.12 §12.6 A안)
· 상품(S14)은 썸네일만 소유: 상품카드의 썸네일 이미지만 상품이 가지고 있고, 상세설명 등 나머지 콘텐츠는 카테고리에서 공통으로 끌어옵니다.
· localStorage 키(값을 저장해 두는 브라우저 저장소의 이름표): 카테고리 high1_ticket_categories_v1 · 상품 high1_ticket_products_v1 · 마진 high1_ticket_margin_master_v1 · 주문(프런트가 저장) high1_ticket_orders_v1

상품에 연결된 쿠폰 스펙을 레벨(성인/아동)별로 한 줄씩 늘어놓습니다. 한 줄에 레벨명·쿠폰명, 옵션 판매가, 그리고 −/+ 수량 스테퍼가 있습니다. 수량은 "담기" 전까지 임시 상태(pending)로만 잡힙니다.

레벨(성인/아동)은 카테고리 뎁스가 아니라 상품 구분자(옵션)입니다. (정책서 v0.12 §12.6)

T10
담기 버튼 — "총 N매 , NN원 담기"
카드에는 소계(합계) 줄을 따로 두지 않고, 담기 버튼 이름에 합쳐 보여줍니다. 옵션 수량을 하나라도 고르면 버튼명이 "총 3매 , ₩150,000 담기"처럼 바뀌고, 아무것도 안 고르면 그냥 "담기"입니다. 누르면 오른쪽 선택 내역(장바구니)에 담깁니다.
— (프런트 계산: 옵션 수량 × 옵션 판매가 합)
pending 수량 × ticketLevelSell 합 → addLabel 문자열
버튼 블록은 카드 우측 50%에 배치. [상세보기]:[담기] 비율 = 3:7. 소계 줄은 삭제.
"담기"만 임시 수량을 장바구니로 확정. 수량 0에서 담기 누르면 "수량을 선택하세요" 안내.
T11
선택 내역 (장바구니)
담은 상품·옵션을 줄 단위로 모아 보여주고, 맨 아래에 총 매수·합계를 표시합니다. "예약하기"를 누르면 결제 페이지로 넘어갑니다. 장바구니 범위는 지금 보고 있는 1뎁스 카테고리 기준이며, 다른 1뎁스로 이동하면 초기화됩니다.
— (프런트 임시 상태. 예약 확정 시 주문 저장)
uiState.ticketCart{deptKey, items[]} → 예약 시 high1_ticket_orders_v1
